# Ручная приёмка шага 2 (brd): план

Что здесь: порядок ручной проверки четырёх подшагов шага 2 на настоящей задаче eddi (DOS-535).
Проверяет ОПЕРАТОР глазами, а не тест: тест говорит «правило соблюдено», глаз говорит «получилось
то, что нужно». Устройство шага — `steps/brd/data-flow.md`, тикеты — `brd-backlog.md`.

**Правило приёмки.** Подшаг закрывает оператор, не зелёный тест. Расхождение живого ответа с
эталоном или с записанным ответом показывается и разбирается ВМЕСТЕ; чинить молча запрещено.

---

## Раскладка каталога подшага

`component-tests/steps/brd/<n>-<имя>/`

```
in/          файлы, которые подшаг читает — байт в байт как в живом прогоне
order.txt    наряд, ушедший в модель          (только 2A и 2C)
raw.json     сырой ответ OpenRouter           (только 2A и 2C)
answer.txt   артефакт из ответа, дословно     (только 2A и 2C)
out/         файлы, которые подшаг написал
```

Вход первого подшага — `sandbox/runbox/eddi/TASK.md`. Дальше **выход предыдущего подшага становится
входом следующего**: это цепочка, а не четыре независимые фикстуры. Расхождение, рождённое на 2A,
обязано доехать до 2D, иначе приёмка проверяет не тот конвейер, который побежит вживую.

---

## Как гоняется подшаг С РОЛЬЮ (2A, 2C)

1. **Наряд.** Собираю из шаблона подшага и входных файлов, печатаю ЦЕЛИКОМ на экран, кладу в
   `order.txt`. Оператор видит, что именно уходит в модель.
2. **Живой вызов.** `curl` на OpenRouter: `qwen/qwen3.6-27b`, `temperature 0`,
   `reasoning: {effort: low}`, инструменты `write` и `workflow_result` — та же поверхность, что у
   хоста pi (`standards/llm.md`). Ответ целиком в `raw.json`.
3. **Отчёт о факте.** Печатаю: секунды · токены выхода · токены рассуждений · **какие инструменты
   позвала роль**. Роль, ушедшая на рельс вопроса вместо `write`, — это результат замера, а не сбой
   стенда, и он печатается вместе с аргументами.
4. **Артефакт.** Достаю `tool_calls[write].arguments.content` в `answer.txt`. **Руками не правлю
   никогда** — портить ответ имеет право только тест, в открытую, на именованном дефекте.
5. **Компонентный тест.** Подкладываю `answer.txt` как записанный ответ и гоняю компонентный тест
   подшага: он ведёт голову подшага ТЕМ ЖЕ приводом `next`/`fold`, что и полоса.
6. **Выход.** Печатаю артефакт целиком, кладу в `out/`. **Останавливаюсь.**

## Как гоняется подшаг БЕЗ РОЛИ (2B, 2D)

1. Юниты подшага.
2. Вызов на НАСТОЯЩЕМ дереве `sandbox/runbox/eddi` — 1854 файла. Счёт файлов и есть предмет
   проверки, на выдуманной фикстуре его проверить нельзя.
3. Печатаю результат и цену (секунды, 0 токенов), кладу в `out/`. **Останавливаюсь.**

## Подшаг 1 — `1-normalize` (2A)

```
вход     in/TASK.md                       заказ eddi, по-русски, 24 строки
наряд    steps/brd/normalize/order.normalize.tpl, слоты {TASK} {STAGING}
роль     normalizer
выход    out/normalized.md                строка на требование: verb | object | instrument | values
гардрейл четыре непустых колонки; значение не оборвано (steps/brd/normalize/normalize.mjs)
опорная цена  60 с · ~4500 токенов выхода (замер 22.08.2026)
```

**Что смотрит оператор:** каждое требование заказа отслеживается в строку; значения (`{id}.glossary.json`,
`/glossarystore/glossaries`, `64 characters`) скопированы целиком; ничего не додумано сверх заказа.

**Известная мера:** эталон `component-tests/etalon-eddi/.agent/normalized.md` — 16 строк. Живой ответ
может дать другое число: это не дефект сам по себе, разбираем построчно.

## Подшаг 2 — `2-hits` (2B)

```
вход     in/normalized.md                 выход подшага 1
         дерево sandbox/runbox/eddi       1854 файла, граница steps/survey-plan/skip.mjs
скрипт   steps/brd/hits/hits.mjs — candidatesOf → hitsOf → tableOf
выход    out/hits.txt                     слово · files N · weight W, по убыванию веса
опорная цена  ~0,6 с · 0 токенов
```

**Что смотрит оператор:** шесть эталонных якорей eddi (`Glossary` · `PromptSnippet` · `agent` ·
`export` · `descriptor` · `configuration`) стоят в таблице с ненулевым счётом; `export` пришёл из
таблицы, а не из русского заказа (по заказу его нет вовсе); служебные слова (`type`, `resource`,
`REST`) видны и по весу ниже.

**Опорные числа:** `Glossary` 1 файл / вес 7,53 · `PromptSnippet` 62 / 3,40 · `export` 92 / 3,00 ·
`descriptor` 290 / 1,86 · `configuration` 631 / 1,08 · `agent` 895 / 0,73.

**Открытый вопрос, который тут виден:** вес не разводит `agent` (0,73) и `version` (1,02) — владелец
работы стоит ниже служебного слова. IDF знает только редкость.

## Подшаг 3 — `3-gate` (2C)

```
вход     in/normalized.md                 выход подшага 1
         in/hits.txt                      выход подшага 2
наряд    steps/brd/gate/order.gate.tpl, слоты {ROWS} {HITS} {FILES} {STAGING} {CHECK}
роль     gate
выход    out/brd.md                       verdict · R1..Rn · analogue · subjects[] · open-questions
гардрейл T1 вердикт из трёх · T2 следствие, не пересказ · T3 созданная сущность в якорях ·
         T4 аналог с ненулевым счётом
опорная цена  12-19 с · ~1000 токенов выхода
```

**Что смотрит оператор:** вердикт `solvable`; следствия — что ИЗМЕНИТСЯ в репозитории, без путей и
чисел; `analogue: PromptSnippet`; якоря против эталонных шести.

**Известная мера:** `component-tests/etalon-eddi/.agent/brd.md`, `subjects[]` — шесть слов. Последний
замер ворот на eddi дал 3 из 6 при потолке 4: `export` и `descriptor` не доходили до таблицы
попаданий. После T02 они в ней есть — это и проверяем.

**Правило селективности снято 23.08.2026.** Доля помеченных файлов печатается в таблице
попаданий как число, но гардрейлом не является: замер на eddi показал, что нужный якорь `agent`
(48,3%) стоит вплотную между фоновыми `value` (51,8%) и `type` (46,0%) — порог по доле не разделяет
нужное и фоновое.

## Подшаг 4 — `4-spread` (2D)

```
вход     in/brd.md                        выход подшага 3
         дерево sandbox/runbox/eddi
скрипт   steps/brd/spread/spread.mjs — filesOf → packagesOf → spreadOf
выход    out/anchors.json                 files · marked · anchors[] · analogue
опорная цена  ~0,4 с · 0 токенов
```

**Что смотрит оператор:** файлы аналога найдены грепом ПО ТЕКСТУ (62 файла для `PromptSnippet`);
пакетная сводка ≤ 10 строк и читается глазами; все 10 файлов, где реально лежит работа DOS-535,
внутри.

**Открытые вопросы:** `marked` — объединение файлов всех якорей, 1154 из 1854 (62% репозитория),
из-за `agent`; артефакт весит 243 КБ, потому что хранит полные списки путей.
