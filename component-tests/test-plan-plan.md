# Пошаговая приёмка конвейера в eddi: тест-план

Что здесь: порядок приёмки доработанного конвейера (T51–T56) на живой задаче DOS-535 — ШАГ ЗА
ШАГОМ, с остановкой после каждого подшага и сверкой результата. Прогон не идёт дальше, пока
текущий шаг не принят. Устройство шагов — `steps/*/data-flow.md`, тикеты доработок —
`redesign-backlog.md` (ревизия 6).

**Правило приёмки.** Шаг закрывает оператор, не зелёный тест и не молчащий скрипт. Расхождение с
эталоном показывается и разбирается ВМЕСТЕ; чинить молча запрещено. Конвейер репозиторно-общий:
правки под eddi-имена в `steps/`, `core/`, `ext/` запрещены — каждый найденный корень становится
тикетом с ОБЩИМ правилом (механический матч, порог из замера), эталонные имена живут только в
`component-tests/`.

## Три источника сравнения

| источник | что это | где |
|---|---|---|
| **эталон v2** | решённая задача (ветка Claude `feat/dos-535-glossary`, коммит `74edeae`), верифицирована против TASK.md: 14/14 решений + два обязательных дозакрытия. Матрица: **16 дельт (7 Added + 9 Changed) + 5 touch** | `component-tests/etalon-eddi/expected.md` |
| **брак** | наш прежний прогон: 7 модулей, RestExport/Import Added, три status="0", AgentConfiguration вне фокуса — 20 красных строк эталона | `sandbox/runbox/eddi-izi-25-08-plan` |
| **v1 (история)** | ручной план «как решал бы агент»; прав v2 там, где они расходятся (пакет, GlossaryConfiguration, MemoryItemConverter, синк-путь) — расхождения перечислены в expected.md | `component-tests/eddi-by-zai.md` |

Сверка — одна команда (две колонки, брак — контрольная):

```bash
node component-tests/etalon-eddi/check.mjs <runbox>/eddi sandbox/runbox/eddi-izi-25-08-plan
```

Скрипт судит tree.xml против матрицы expected.md (дельты — красным при отсутствии/несовпадении,
touch — мягко), плюс живые правила: T6 (seed с Added), F15 (status="0"), T51 (configs~agents в
фокусе, доки-клетки), T55 (аналоги в ripple), три имени в карте. Смена эталона = правка expected.md,
код сверки не трогается.

## Механика: как прогон останавливается и продолжается

**Stop-after.** Полоса поддерживает остановку после именованного подшага: `bin/run.mjs
--cwd=<каталог> --key=DOS-535 --stop-after=<id> --go`. После завершения подшага `<id>` прогон
возвращает `ok({stopped: id})` и процесс заканчивается — дальше не идёт.

**Продолжение.** `ext/recon.mjs` штампует завершённые шаги по артефактам на диске — следующий
запуск (с тем же или следующим `--stop-after`) продолжает с места остановки; кэш `.izi/parts`
делает повторный вход дешёвым. Полумёртвый прогон чинится тем же способом: недостающие части роя
досчитываются, зелёные берутся из кэша.

**Обрыв 402.** OpenRouter даёт `in_flight_budget_exhausted` при широком рое: перезапуск через 120 с
(Retry-After), resume подхватывает с диска. Обёртка — цикл перезапусков, не ручное жатьё.

**Модель.** `qwen/qwen3.6-27b` (решение оператора): роли резолвят алиас `execution` в неё.

**13 станций** (в порядке полосы):

```
task · brd/normalize · brd/anchors · scope/plan · scope/focus · scope/parts · graph ·
intake · weight · ripple · plan/values · plan/tree · plan/flows
```

## Подготовка runbox/eddi с нуля

```bash
node --test                                    # вся линия зелёная — иначе прогона нет
node bin/install.mjs --to=sandbox/runbox/eddi  # харнес с T51–T56 + docs-фиксом фокуса
grep -c allOf sandbox/runbox/eddi/workflows/izi.js   # ≥ 1 — новый харнес, не старая копия
cd sandbox/runbox/eddi && ls TASK.md                 # заказ на месте
```

Старое содержимое `.agent/` уходит в архив (`mv .agent .agent.prev-<дата>`), кэш `.izi/parts`
остаётся — он безразличен к составу прогона. Каталог запуска — сам `runbox/eddi` (пути
резолвятся от cwd, AGENTS.md §6).

## Общий протокол станции

1. **Запуск.** `node bin/run.mjs --cwd=sandbox/runbox/eddi --key=DOS-535 --stop-after=<id> --go`
   (первая станция — без стоп-флага не запускать вовсе: без него полоса идёт до конца).
2. **Машина.** Артефакт станции существует и проходит свой суд (полоса сама судит каждый артефакт —
   дошедший до остановки шаг ЗЕЛЁНЫЙ по правилам полосы). Затем `check.mjs` — факты против эталона.
3. **Глаз.** Пункты «что смотрит оператор» из таблицы станций ниже.
4. **Стоп-условия.** Красная строка `check.mjs`, расхождение с эталоном на глаз, вопрос оператору,
   обрыв связи дважды на одном ходе — прогон стоит, разбор.
5. **Принято — двигаем `--stop-after` на следующую станцию.** Не принято — протокол красного шага.

## Журнал приёмки — как отмечается проверенный шаг

`component-tests/etalon-eddi/acceptance.md` — таблица на 13 станций (+эпилог tickets), одна строка
на станцию: дата · артефакт с sha1 · счёт `check.mjs` · вердикт оператора. Статусы: `—` не дошли ·
`ok` принято · `red` разбор (ссылка на тикет) · `redo` перепринята после починки · `skip` пропущена
решением оператора.

Два правила:

- **Строку закрывает оператор.** Агент заносит факт (артефакт, счёт сверки), оператор — вердикт.
  Зелёный артефакт на диске без вердикта станцию не закрывает.
- **Прогон и приёмка — разные состояния.** Что посчитано, живёт в артефактах и восстанавливается
  recon'ом при перезапуске; ПРИНЯТО или НЕТ — только в журнале. Пережитый прогон не двигает строки.

## Протокол красного шага

1. **Стоим.** Прогон не продолжается, артефакты не правятся руками — никогда.
2. **Фиксируем.** Журнал `~/.pi/workflows/projects/<форма>-*/sessions/*/runs/<runId>/journal.json`
   + расхождение артефакта с эталоном (`check.mjs` печатает) + сравнение с браком (что уже было
   лучше/хуже).
3. **Корень.** Именуется механически: какая фаза потеряла факт (фокус не купил / FRD не назвал /
   ripple не показал / суд не поймал). «Модель ошиблась» — не корень.
4. **Предложение.** Тикет в `redesign-backlog.md`: правило ОБЩЕЕ (никаких eddi-имён), с юнит-швом и
   мерой, на которой правило куплено. Починка — только после решения оператора.
5. **Перезапуск с той же станции.** `--stop-after=<та же>`: recon пропускает зелёное, красный шаг
   пересчитывается. Перепроверка `check.mjs` — цикл замкнулся.

## Предсказанные красные (честно: где ждём расхождение с эталоном v2)

- **MemoryItemConverter как точка подстановки.** Брак назвал AgentExecutionHelper; вектор T55 даёт
  конвертеру доехать через соседство PromptSnippetService, но подстраховки нет. Если дерево снова
  назовёт не тот модуль — корень в фокусе/ряби (клетка engine/memory), не в модели.
- **Синк-модули до дельт.** IResourceSource, ZipResourceSource, RemoteApiResourceSource,
  StructuralMatcher, UpgradeExecutor — эталон требует их Changed; в браке их не было вовсе.
- **AgentConfiguration Changed** — прямое следствие T51; если фокус взял клетку, а FRD не дал
  дельту — корень в intake (F14 должен был загореться).
- **RestExport/Import Changed** — судья T6 обязан отбить Added (в браке проехало).

## Что НЕ проверяется этим планом

- Юниты и компонентные тесты — линия `node --test` зелёная перед прогоном, пересказа нет.
- Дефекты решения Claude — эталон фиксирует их как дозакрытия (синк-перепривязка, invalidateCache),
  чинятся в `eddi-claude`, не здесь.
- Живой pi с чат-моделью — прогон идёт headless-раннером (`bin/run.mjs`), TUI-приёмка отдельно.
