## 1. Диагноз: что именно сломано

**Шага как модуля нет.** Шаг — функция внутри `workflows/izi.js` (2 169 строк, 29 функций;
`designing()` — 98 строк, `portions()` — 106). Файл не модуль: хост берёт его ТЕКСТ, оборачивает в
async-стрелку и исполняет в vm (`pi-extensible-workflows/packages/core/src/execution.ts:302`), где
`import`, `require`, `module`, `Function`, `eval`, `Date`, `process` = `undefined` (`:299`).
Экспортов нет. Импортировать шаг в тест нельзя — исполнение файла означает запуск конвейера.

Отсюда всё остальное:

1. **Компонентный тест переписывает полосу руками** (`steps/plan/tree/component/`, ~15 строк копии) —
   и проверенный им наряд отличается от живого ровно на эту копию.
2. **Не проверяет никто**: выбор «первый заход или починка», адресат блокера, пропуск зелёной порции,
   исчерпание `LOOPS`, рельса вопроса оператору. Единственный способ узнать — живой прогон, 4–9 минут
   за круг роли.
3. **Ошибки — исключения, а не значения**: `exit(err(...))` разматывает стек; ROP в голове нет.
4. **Состояние размазано** по диску, по `.agent/`, по локальным переменным полосы; «с чего
   продолжать» решают три разных механизма.
5. **Трейса прогона нет** — есть журнал хоста, но по нему нельзя ни восстановить шаг, ни взять
   заглушку для теста.

## 2. Решение: голова + единообразные модули + привод

**Голова.** `workflows/izi.js` — линейная ROP-цепочка вызовов шагов, своей логики нет, ошибка
поднимается непреобразованной, мапится один раз на краю. Ровно `ProcessValidate` из `head.go`.

**Шаг — модуль.** Обычный ESM-модуль в `steps/`, с `import`, `fs` и `node --test`. Один вход
(состояние), один выход (состояние), вертикальное подчинение: шаг зовёт только свою пятёрку.

**Пятёрка внутри шага, одна на все шаги** — `cut → order → ask → judge → route` (скрипт → LLM →
скрипт-судья → скрипт-резка → скрипт-маршрутизатор). Форма фиксирована и нарушать её нельзя.

**Привод.** Между головой и модулем — граница процессов: функции хоста живут в другом процессе, и
аргумент едет по RPC **одним JSON-объектом** (`execution.ts:234-236`). Колбэк не проедет, поэтому
модуль не может получить `agent` заглушкой. Значит модуль **говорит, что сделать**, а полоса делает:

```
next(state)        → { do: "role" | "roles" | "ask" | "say" | "done" | "err", … }
fold(state, event) → state'
```

`next` **решает и готовит доставку** (читает вход, собирает наряд, чистит staging-путь порции,
кладёт `pending.json` перед вопросом), `fold` **принимает ответ и судит**. Объявить `next` чистой
нельзя: скелет считается из требования, наряд собирается из живых образцов — это чтение диска, и
правило «ни `fs`» краснело бы на первом же шаге.

> **Отвергнутый вариант.** Научить `ext/` звать модель самому по HTTP — тогда шаг стал бы буквально
> `head.go` с внедрёнными зависимостями, а `izi.js` — пятистрочным пускателем. Цена: уходит `agent()`,
> а с ним роли по имени файла, журнал прогона, `checkpoint` оператору, учёт стоимости и
> возобновляемость — то есть весь харнес, ради которого выбран `pi`. Не берём.

**Две общие службы** (требование `tasks/redesign.md`): `state` — владелец формы состояния и истории;
`runlog` — XML-трейс прогона. Обе с явным API, обе зовутся любым шагом.

## 3. Как будет выглядеть код

Три листинга ниже — не эскиз, а контракт: T05, T06 и `standards/component-test.md` копируют их
буквально. Всё, что в них написано, куплено либо контрактом хоста (`validation.js`), либо живым

### `workflows/izi.js` — весь файл

```js
// MODULE_CONTRACT: workflows/izi.js — ГОЛОВА: линейная ROP-цепочка шагов. Своей логики нет.
// io: none. EXTERNAL_DEPENDENCY: sandbox — agent, parallel, checkpoint, log, args;
//     ext — stepStart, stepNext, stepFold. Их отсутствие читается как «X is not defined»
//     и означает: расширение старше полосы, ПЕРЕЗАПУСТИ pi.

const ok  = (fields) => ({ track: "ok", code: 0, ...fields });
const err = (kind, fields) => ({ track: "err", kind, code: kind === "crashed" ? 2 : 10, ...fields });
const ENVELOPE = { /* … outputSchema конверта роли, как сегодня в izi.js:86-135 … */ };

// РОЙ ЛИТЕРАЛЕН ПО КОНТРАКТУ ХОСТА. parallel требует ЛИТЕРАЛЬНУЮ строку имени и ЛИТЕРАЛЬНЫЙ объект
// задач: хост валидирует ИСХОДНИК до исполнения (validation.js:862). Динамический
// `parallel(i.at, Object.fromEntries(...))` не запускается вообще — «The workflow metadata is
// invalid: parallel requires an operation name string and tasks record», ноль потраченных токенов и
// ноль диагностики. Это уже оплачено живым запуском (izi.js:663-681). Ширина — литерал ЭТОГО файла;
// budgets.maxParallel умеет её только ПОНИЗИТЬ. Порций больше ширины — `next` эмитит их пачками.
const SWARM = 8;
const seat = (i) => (calls) => calls[i] ? agent(calls[i].text, { role: calls[i].role, outputSchema: ENVELOPE }) : null;

const PRIMITIVES = {
  role:  (i) => agent(i.text, { role: i.role, outputSchema: ENVELOPE }),
  roles: (i) => parallel("roles", {
           s0: () => seat(0)(i.calls), s1: () => seat(1)(i.calls), s2: () => seat(2)(i.calls), s3: () => seat(3)(i.calls),
           s4: () => seat(4)(i.calls), s5: () => seat(5)(i.calls), s6: () => seat(6)(i.calls), s7: () => seat(7)(i.calls) }),
  // checkpoint берёт ОДИН объект и ровно три поля (validation.js:15). ИМЯ КЛЮЧУЕТ ПАУЗУ: два хода с
  // одним именем — одна пауза, и второй вопрос оператор не увидит никогда (izi.js:317-320). Имя и
  // урезанный до 1024 байт prompt считает ШАГ и кладёт в инструкцию — полоса текстов не собирает.
  ask:   (i) => checkpoint({ name: i.name, prompt: i.prompt, context: { pending: ".agent/pending.json" } }),
  say:   (i) => log(i.line),
};
const VOID = new Set(["say"]);   // слова, после которых событие пусто: fold зовётся, но складывать нечего

// Круги внутри шага наружу не видны — как не виден снаружи `for` внутри функции.
// СЛОВО, КОТОРОГО ПОЛОСА НЕ ЗНАЕТ, — ОТКАЗ С ИМЕНЕМ, а не TypeError: расширение читается при старте
// сессии pi, этот файл — при каждом прогоне, поэтому новое слово в старой полосе штатно возможно.
const run = async (id, state) => {
  for (;;) {
    const it = await stepNext({ id, state });
    if (it.do === "done") return ok(it.state);
    if (it.do === "err")  return err(it.code, { subject: it.subject, evidence: it.evidence });
    const primitive = PRIMITIVES[it.do];
    if (!primitive) return err("crashed", { subject: `шаг ${id} просит «${it.do}» — полоса такого не умеет: перезапусти pi` });
    const result = await primitive(it);
    const folded = await stepFold({ id, state, event: { do: it.do, result: VOID.has(it.do) ? null : result } });
    if (folded.track === "err") return folded;          // ROP: отказ fold поднимается, а не рушит state
    state = folded.value;
  }
};

async function plan(state) {
  const values = await run("plan/values", state);      if (values.track === "err") return values;
  const tree   = await run("plan/tree", values.value); if (tree.track === "err")   return tree;
  return await run("plan/flows", tree.value);
}

try {
  const state = await stepStart({ args });

  const task    = await run("task", state);            if (task.track === "err")   return task;
  const brd     = await run("brd", task.value);        if (brd.track === "err")    return brd;
  const scope   = await run("scope", brd.value);       if (scope.track === "err")  return scope;
  const graph   = await run("graph", scope.value);     if (graph.track === "err")  return graph;
  const intake  = await run("intake", graph.value);    if (intake.track === "err") return intake;
  const weight  = await run("weight", intake.value);   if (weight.track === "err") return weight;
  const ripple  = await run("ripple", weight.value);   if (ripple.track === "err") return ripple;

  // ГРАНИЦА ПЕРВОЙ ПОСТАВКИ. plan/book, review, gate1 объявлены в дереве с ship="0" и здесь НЕ
  // зовутся: мост на неизвестный id обязан вернуть отказ, и прогон кончался бы ошибкой на успехе.
  return await plan(ripple.value);
} catch (e) {                      // адаптер на краю — единственное место, где ошибка мапится
  const msg = String((e && e.message) || e);
  const HOST = ["agent", "parallel", "checkpoint", "log", "stepStart", "stepNext", "stepFold"];
  // Сверяем ИМЯ, а не форму сообщения: «ok is not defined» — дефект этого файла, и «перезапусти pi»
  // увело бы оператора в сторону на каждом прогоне.
  if (HOST.some((n) => msg === `${n} is not defined`)) return err("crashed", { subject: `${msg} — функции хоста нет в этой сессии pi: перезапусти pi` });
  return err("crashed", { subject: msg });
}
```

Восемьдесят строк вместо 2 169, и половина из них — комментарии, купленные живыми прогонами.
Программа конвейера читается сверху вниз одним взглядом.

### `steps/plan/tree/tree.step.mjs` — модуль шага

Два вызова наружу, и они делят работу по одной границе: **`next` решает и готовит доставку, `fold`
принимает ответ и судит.** Ни один из них не делает работы другого.

```js
// MODULE_CONTRACT: шаг 9B — дерево модулей работы. Голова над своей пятёркой.
// Interface: id, next, fold
export const id = "plan/tree"

// FUNCTION_CONTRACT: next — ЧТО делать дальше.
//   io: ЧИТАЕТ вход (frd.xml, ripple.xml, appgraph.xml, файлы образцов) и ПИШЕТ ровно подготовку
//       доставки: чистит staging-путь порции и кладёт .agent/pending.json перед вопросом.
//       НЕ зовёт модель, НЕ судит, НЕ продвигает артефакт — это и сторожит шов 2.
//   Почему не «чистая»: скелет считается из требования, наряд собирается из шаблона и живых
//   образцов — всё это чтение диска. Объявить next чистой и звать из него cut/order значило бы
//   написать правило, которое краснеет на первом же шаге.
//   Почему чистка staging — здесь: файл прошлого круга, оставшийся на пути доставки, судится как
//   ответ этого круга. Куплено прогоном da99bbae (izi.js:1422-1437, WRITE_TAKES).
export const next = (state) => {
  const bad = inputs(state)                          // ПЕРВЫЙ ХОД ШАГА — суд ВХОДА, не выхода
  if (bad)                          return { do: "err", code: "blocked", subject: bad }
  if (state.question)               return ask(state)          // { do:"ask", name, prompt, items }
  const p = portions(state)                          // список порций из состояния, не счётчик
  if (!p.length)                    return { do: "say", line: skeleton(state).line }
  const dead = p.find((x) => x.round > state.budgets.loops)
  if (dead)                         return { do: "err", code: "escalate", subject: dead.blockers }
  const todo = p.filter((x) => x.status === "todo")
  if (!todo.length)                 return { do: "done", state }
  return order(state, todo)          // { do:"role", … } либо { do:"roles", calls:[…≤ SWARM] }
}

// FUNCTION_CONTRACT: fold — куда кладётся ответ. io: СУДИТ, кладёт вердикт, продвигает.
//   АРТЕФАКТ ПИШЕТ РОЛЬ, А НЕ fold. Конверт несёт ПУТЬ (ENVELOPE.artifact — строка), поля с текстом
//   в нём нет и быть не может: документ по RPC не едет. fold сверяет, что роль записала ТУДА, куда
//   её послали, — это и есть «проверь staging-путь прежде, чем продвигать» (CLAUDE.md, огр. 2).
export const fold = (state, event) => {
  if (event.do === "say")   return ok(state)                       // лог состояния не меняет
  if (event.do === "ask")   return answered(state, event.result)   // approved — барьер над ФАКТОМ:
                                                                   // ответ ищется на диске по номеру
  const verdicts = []
  for (const [id, env] of envelopes(event)) {         // одиночный конверт и запись роя — один разбор
    if (!env || env.track === "err") { verdicts.push(refused(state, id, env)); continue }
    verdicts.push(judge(state, id, env))              // ← гардрейл порции; тотален, не бросает
  }
  return route(put(state, verdicts))                  // склейка → гардрейл целого → продвижение
}
```

Четыре правила, которые здесь видно и которые нарушать нельзя:

- **`refused` не тратит круг и не трогает staging.** Обрыв связи — не ошибка роли; `kind:"question"`
  уезжает в `state.question`, `kind:"lookup"` — скрипту-ответчику. Без этой ветви обрыв съедает
  бюджет починки и портит прошлый ответ.
- **Пятёрка тотальна.** `cut`, `order`, `judge`, `route` не бросают: битый XML — это ВЕРДИКТ
  `invalid`, а не исключение. Договор уже написан в `ext/index.mjs:40` и переезжает в
  `standards/workflow-design.md` правилом 9. Иначе один незакрытый тег уносит прогон на 40 минут
  мимо всей ROP-цепочки.
- **Состояние строит только конструктор.** `put(state, patch)` вместо `{...state, …}`: иначе
  valid-by-construction срабатывает один раз за прогон, а следующие N состояний создаются в обход.
- **Круг считается по ПОРЦИИ, не по шагу.** Иначе первая порция съедает бюджет всего шага, и
  порции 3 и 4 не пробуются ни разу.

## 4. Тесты: что удаляем и что остаётся

Удаляются **все** существующие тесты. Остаются ровно две категории — по формуле из
`../rationaldev-ai-sdlc` и статьи «Правильность программы»:

**На модуль шага — компонентный тест, три сценария** (шаг с ЛЛМ):

| # | сценарий | что доказывает |
|---|---|---|
| 1 | успех | шаг проходит целиком на записанном ответе модели, артефакт продвинут |
| 2 | нарушение | гардрейл поймал, артефакт НЕ продвинут, наряд починки несёт адрес правки |
| 3 | отказ ЛЛМ | обрыв связи — шаг не закрывается, состояние не портится, круг НЕ тратится |

Шаг без ЛЛМ (`task`, `graph`, `weight`, `ripple`) — два сценария: успех и нарушение.
Шаг с ПАРАЛЛЕЛЬНЫМИ порциями (`scope`, `plan/flows`) — сценарий 3 раздваивается: упала одна порция
из семи (соседи не портятся, шаг не закрывается) и упали все. Итого у них четыре.

**На гардрейл — юниты по формуле** `N = 1 happy + Σ различимых ветвей + 1 молчание на каждый внешний
операнд`. Молчание — обязательная третья ветвь (`standards/guardrail.md`): при отсутствующем
операнде правило обязано МОЛЧАТЬ, а не краснеть (тупиковый блокер, который роли нечем закрыть) и не
зеленеть (мусор проехал).

**Гардрейл шага — не один модуль, а судья на правило.** Измерено 21.08.2026 по действующему коду:

| гардрейл | различимых блокеров | правил |
|---|---|---|
| `steps/intake/frd.mjs` | 49 | 20 (F0…F14 с подпунктами) |
| `steps/scope/part.mjs` | 31 | 18 (S1…S10, P2…P9) |
| `steps/graph/graph.mjs` | 26 | — |
| `steps/plan/tree/tree.mjs` | 17 | 5 (T1…T5) |
| `steps/plan/flows/flows.mjs` | 15 | 7 (F0, F6…F11) |
| `steps/plan/values/values.mjs` | 13 | — |
| `steps/brd/brd.mjs` | 12 | — |
| `steps/ripple/ripple.mjs` | 2 | — |
| `steps/weight`, `steps/task` | 0 (вердикт без списка блокеров) | — |

Отсюда **два следствия, и оба обязательны**:

1. Число юнитов — это ИЗМЕРЕНИЕ, а не выбор. Порядка 165 ветвей плюс happy и молчания на каждого
   судью. Хочешь меньше тестов — сокращай ПРАВИЛА, а не тесты; иначе правило остаётся комментарием.
2. Судья на 49 ветвей — не модуль, а свалка: `standards/code.md` прямо велит декомпозировать, а не
   писать пятидесятый тест. `judge` каждого шага режется на судей ПО ПРАВИЛУ (`T1.mjs`, `T2.mjs`, …),
   у каждого свои юниты по формуле, а `judge.mjs` остаётся головой, которая их складывает — и
   головы юнитами не покрываются.

Заглушка ответа модели — **записанный** ответ, а не выдуманный: берётся из `.agent/runlog.xml`
живого прогона либо снимается `curl`'ом на наряд, который собирает этот же код. Правила — в

## 5. Правила для агента и автопроверки

Правила пишутся в `standards/workflow-design.md`, каждое — со швом, который краснеет при нарушении.
Шов доказывается реинтродукцией дефекта: ломаем правило — шов краснеет — чиним обратно.

| # | правило | автопроверка |
|---|---|---|
| 1 | шаг выставляет ровно `id`, `next`, `fold` | линт по экспортам `steps/**.step.mjs` |
| 2 | `next` не зовёт модель и не продвигает; пишет только подготовку доставки | линт по графу вызовов `next`: нет `agent`, `promote`, `write` вне `prepare` |
| 3 | слово инструкции известно всем троим | шов: слова модулей ↔ ключи `PRIMITIVES` ↔ ветви `drive` компонентных, попарно |
| 4 | вердикт каждого хода лежит в состоянии | линт: `fold` вернул состояние, где `verdicts` длиннее ровно на число конвертов хода |
| 5 | артефакт продвигается только после зелёного вердикта | шов на `promote` в `route` |
| 6 | в состоянии нет документов шага | линт: ни одно поле не держит текст артефакта; предел размера состояния |
| 7 | голова без логики | линт: `izi.js` ≤ 90 строк, ветвлений сверх словаря нет |
| 8 | у шага есть компонентный тест | линт: на каждый `steps/**.step.mjs` есть `component/` |
| 9 | пятёрка тотальна | линт: разбор чужого текста в `cut`/`judge` обёрнут; юнит «битый XML → вердикт, не бросок» |
| 10 | рой литерален | линт по `workflows/izi.js`: у `parallel` первый аргумент — строковый литерал, второй — объектный |
| 11 | шаг судит СВОЙ вход | линт: `next` первым делом зовёт `inputs(state)`; юнит «нет входного артефакта → отказ с именем файла» |
| 12 | имя роли известно хосту | шов: имена ролей в инструкциях ↔ файлы в `roleDirectories` |

Правила 9–12 куплены разбором этого плана критиками 21.08.2026 и без них не ловятся ничем, кроме
живого прогона.

## 7. Контракты между модулями: нужны ли отдельным документом

**Нет, отдельного `contracts.md` не заводим.** У pinout он существует потому, что там контракт
описывается ДО кода и по нему пишет другой агент. Здесь контракт модуля живёт в самом модуле —
`MODULE_CONTRACT` / `FUNCTION_CONTRACT` (`standards/code.md`), а форма, общая для всех шагов, одна и
описана в `plan-app-graph.xml`: `id`, `next`, `fold`, пятёрка внутри. Дублировать её отдельным файлом
значит завести второе место для одного правила — запрещено `standards/code.md`, ограничение 1.
