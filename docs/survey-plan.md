# Шаг 3 `survey-plan` — раскладка разведки и вычисленные факты

Карточка шага — `docs/workflow.md` §3.3, обоснование — `docs/concept.md` («Разведка (шаги 3–5)»).
Здесь: что строится, каким кодом и как встаёт в `workflows/izi.js`.

**Источник истины — файлы, а не этот документ.** Код: `steps/survey-plan/plan.mjs` (+ `skip.mjs`,
их тесты), `steps/scope/{source,edges,computed}.mjs`, `ext/index.mjs::survey`, фаза
`workflows/izi.js::surveyPlan`.

---

## 1. Что решает шаг

Рой скаутов (шаг 4) не грепает и не выбирает себе файлы — всё приезжает в наряде. Значит кто-то
обязан это посчитать. Считает **скрипт за 0 токенов**, и решений у него теперь два:

| | |
|---|---|
| **вход** | дерево файлов от cwd прогона, `.agent/brd.md` (только `subjects[]`) |
| **выход 1** | `.agent/survey-plan.json` — клетки роя, у каждого файла `sha1` |
| **выход 2** | `.agent/graph-computed.xml` — рёбра, http-маршруты, драйверы, границы вычислимого |
| **род** | `script` — роли нет, вызовов модели нет, **оператора нет** |
| **приёмка** | клетки покрывают ВСЕ просканированные файлы без пересечений и без потерь |
| **вырождение** | сканировать нечего (ноль файлов) → `blocked` с диагнозом |

### Якорь — пометка, а не фильтр

Первая редакция брала в план только файлы, попавшие под якоря `subjects[]`. Живой факт на
квaркус-проекте это опроверг: `Legume.java`, `LegumeResource.java` и два их теста под якоря не
попали, а требование R3 «существующие вызовы не меняются» — именно про них. **Ложный пропуск здесь
дороже ложного попадания**: лишний файл стоит скауту абзаца, потерянный — стоит графу узла, которого
никто уже не хватится.

**Матч якоря — подстрока, без учёта регистра**, по пути И по тексту. Матч по границе слова проверен
и отвергнут фактом: он теряет `fruits` при якоре `fruit` и `FruitResourceIT` целиком.

### Клетка — поддерево, id — путь

Клетка закрывается по **20 файлам ИЛИ ~200 КБ**, но режется не плоский список, а ДЕРЕВО: поддерево
целиком становится клеткой, если влезает в оба потолка; иначе каталог раскрывается — сначала
подкаталоги по тому же правилу, потом собственные файлы каталога, порезанные последовательно.

`id` выводится из пути (`src/main/java` → `src~main~java`, корень → `root`, кусок не влезшего
каталога → `src~~1`). Это не косметика, а **условие кэша шага 4**: при плоской резке с id `c1`,
`c2`, … один добавленный файл сдвигал состав всех последующих клеток, и переиспользовать было
нечего. Замер на eddi: плоская резка — 100 клеток по 184 КБ, по поддеревьям — 291 клетка с медианой
32 КБ.

Клетка хребта зовётся **`spine`** — именем рода, а не позицией. Каталог, случайно названный так же,
получает `spine~~2`: суффикс `~~` недостижим отображением пути, поэтому столкновение невозможно по
форме, а не по везению.

Число клеток не ограничено: `maxParallel = 8` у pi — размер БАТЧА, а не потолок их количества.

### Граница обхода — cwd прогона минус предикат отсева

`docs/concept.md` называл входом каталог `app/`. Литерал снят решением оператора: он диктует чужому
репозиторию раскладку ровно там, где концепт требует обратного. В реальных репозиториях код лежит в
`src/`, `lib/`, `packages/`, `cmd/`.

Отсев живёт в `steps/survey-plan/skip.mjs` — **чистым предикатом со своими юнитами**, а не списком
внутри обхода. Причина: живой прогон на форме quarkus не краснеет ни на одном правиле, потому что в
этой форме нет ни `vendor/`, ни `.min.js`, ни собранного фронтенда — доказать правило может только
юнит, и по паре случаев (оставили / выбросили) на каждое.

| правило | что отсеивает | что НЕ отсеивает |
|---|---|---|
| харнес | `workflows/ steps/ core/ bin/ ext/ prompts/` — их копирует установщик | одноимённый каталог проекта — **принятая цена, названа вслух** |
| вывод сборки | `node_modules dist build target out coverage`, точечные каталоги | `.github` — там CI |
| вендоренное | `vendor/ third_party/ Pods/ Godeps/`, `mvnw`, `gradlew`, lock-файлы | `go.mod`, `package.json` — это хребет |
| генерённое | `*.pb.go`, `zz_generated*`, `mock_*`, `*_pb2.py`, `*.generated.*` | `mockingbird.go`, `generation.go` |
| собранный фронтенд | `app.4f3c2b1a.js` (хеш в имени), `*.min.js`, `*.map` | `app.config.js`, `admin.js` |
| ассеты и бинари | шрифты, картинки, медиа, архивы, `.so/.class/.wasm`, офис | `Logo.java`, `png.go` |
| ignore-файлы | `.gitignore`, `.dockerignore`, `.gitattributes`, `.npmignore` | `.env`, `.editorconfig`, `.github/` — это хребет |
| входы харнеса | `TASK.md`, `izi.config.json` — конвейер, не приложение | всё прочее в корне |

Строка про ignore-файлы куплена парой прогонов на одном дереве: `615192d7` сделал `.gitignore` узлом
графа, `dc415b95` закрыл тот же файл `<gap>`. Два прогона — два графа, и ни одно чтение не назвать
неверным: с таким файлом ни один шаг полосы ничего сделать не может.

Строка про входы харнеса куплена живым прогоном `6e3b9455`: `TASK.md` попал в клетку, и часть вернулась с
`<module path="TASK.md">` — требование оператора стало узлом графа приложения. Скаут ни при чём:
наряд обязывает закрыть каждый файл клетки.

**Файл крупнее 4 МБ не читается, но и не исчезает**: он уезжает в `skipped` плана с размером и
причиной. Потолок раньше был 512 КБ и выбрасывал файл из плана молча — на eddi так терялось 10
узлов. Потолок опущен до роли чтения диска: в наряд теперь едет выжимка, а не текст, и цена крупного
файла в наряде больше не пропорциональна его размеру.

### Клетка `spine` — хребет: манифест сборки и конфиги

Граф шага 5 обязан ответить на шесть вопросов: **как тестировать**, **как менять**, **как выключают**
(механизм тоглов), **как здесь ветвятся**, **чем описан внешний контракт** и **с какими внешними
системами** проект говорит (последнее — из конфигурации, поэтому в клетку хребта собираются и
`resources/application.*`, `.env`, `config/`). Живой факт: в квaркус-проекте единственное место, где
написано про раннер, — `pom.xml`; в общей клетке скаут описал бы его как ещё один модуль. Хребет
вынесен отдельной клеткой **ради наряда**: не «опиши модули», а «назови команду сборки, раннер
тестов, механизм тоглов и соглашение о ветках — или объяви, что их нет».

| экосистема / слой | что попадает в `spine` |
|---|---|
| Maven | `pom.xml` |
| Gradle | `build.gradle(.kts)`, `settings.gradle(.kts)`, `gradle.properties` |
| Go | `go.mod`, `Makefile` |
| Node | `package.json` |
| конфиг-слой любой | `**/resources/application.*`, `.env*`, `config/*` |
| CI | `.github/workflows/*`, `.gitlab-ci.yml`, `Jenkinsfile` |
| соглашения | `README*`, `CONTRIBUTING*` |

Ни одно имя не совпало → клетки хребта нет, граф пишет «раннер не найден», вопрос уезжает оператору
на шаге 10: список — ускоритель, а не условие работы.

### Форма артефакта

```json
{
  "files": 19, "bytes": 41230,
  "subjects": ["fruit", "search", "limit"],
  "gaps": ["search"],
  "skipped": ["assets/dump.bin (9400000 b > 4194304)"],
  "cells": [
    { "id": "spine", "kind": "spine", "subjects": [], "bytes": 3791,
      "files": [ { "path": "pom.xml", "bytes": 3740, "sha1": "9ab…", "subjects": [] } ] },
    { "id": "src~main", "kind": "survey", "subjects": ["fruit", "limit"], "bytes": 3452,
      "files": [ { "path": "src/main/java/org/acme/rest/json/FruitResource.java", "bytes": 1210, "sha1": "1c4…", "subjects": ["fruit"] } ] }
  ]
}
```

Поля стоят ради ШАГОВ 4–5, а не ради красоты: `subjects` целиком — шаг 5 проверяет «ни один якорь не
потерян», и проверка не должна ничего выводить; `kind` — шаг 4 выбирает наряд по полю, а не разбором
строки; `bytes` — стоимость клетки видна до запуска роя; `sha1` — ключ кэша шага 4; `skipped` —
всё, что не прочитано, названо, а не умолчано.

## 2. Вычисленные факты — второй выход шага

Один проход по дереву кормит трёх потребителей: якоря, `sha1` и **факты о коде**. Текст файла не
переживает итерацию — в памяти остаются только выжатые из него факты.

```
steps/scope/source.mjs    язык · импорты · объявления с видимостью · драйверы    (чистое)
steps/scope/edges.mjs     импорт × индекс путей → ребро, либо ОТКАЗ с уликой     (чистое)
steps/scope/computed.mjs  маршруты из аннотаций + сериализация артефакта          (чистое)
```

Сюда же уехал ПОТРЕБИТЕЛЬ маршрута: строковый литерал, точно совпавший с путём известного `<api>`,
даёт `<use at path via>` — так `fruits.html` перестал быть узлом без связей.

Правила разрешения импорта: **java** — полный пакет как путь (`org.acme.Fruit` →
`**/org/acme/Fruit.java`), плюс тип своего пакета без импорта вовсе; **go** — `module` из `go.mod`
превращает путь импорта в каталог; **ts/js** — относительные пути с достройкой расширения и
`index.*`; **python** — модуль как файл. Всё прочее объявляется `edges="no-rules"`.

Две вещи, ради которых артефакт вообще существует в такой форме:

- **`<lang>` пишется всегда и первым.** «Рёбер ноль» и «правил для языка нет» обязаны различаться,
  иначе дефект `337b957f` (молчание вместо ответа) переезжает с роли на скрипт, где его уже никто не
  заметит. Go без `go.mod` объявляется так же: правило есть, применить не к чему.
- **Две цели у одного импорта — `<ambiguous>`, а не выбор.** Два `Model.java` в разных модулях
  монорепо неразличимы по хвосту пакета; выбранный наугад неотличим от факта.

Подробности грамматики и границ — `docs/scope.md` §2б, §3.

## 3. Раскладка среза

```
steps/survey-plan/
  plan.mjs        ЧИСТОЕ ядро: newPlan({files, spine, subjects, cellFiles, cellBytes}) -> Result
  plan.test.mjs   happy · шов устойчивости id · спуск по дереву · столкновение id · no-files
  skip.mjs        ЧИСТЫЙ предикат отсева: skipDir · skipFile · whySkipped
  skip.test.mjs   по паре случаев (оставили / выбросили) на каждое правило
```

Роли нет → нет `<role>.md`, нет `order.tpl`, нет staging/promote: staging существует, чтобы артефакт
РОЛИ не закрыл шаг до зелёного чека. Здесь артефакт производит сам чек — он пишется **после**
решения его принять и только на нём (`standards/code.md`, ограничение 6).

Io-обвязка — функция хоста `ext/index.mjs::survey`, по тому же контракту, что `checkTask`/`checkBrd`:
пути якорятся к `context.run.cwd`, «нечего картировать» — это ДАННЫЕ (`ok:false`), а не исключение.
Шаг логирует стоимость роя и **границы вычислимого** ДО того, как потрачен первый токен:

```
survey-plan: files=19 bytes=41230 cells=2 edges=4 [(unknown):no-rules:10 java:edges:9]
```

## 4. Чего этот срез НЕ делает

- не зовёт скаутов (шаг 4) и не строит граф (шаг 5) — только раскладка и вычислимые факты;
- не читает содержимое требований `R<n>` — из BRD берёт **только** `subjects[]`, и то как пометку;
- не спрашивает оператора вовсе: раскладка вычислима, а вычислимое считает скрипт за 0 токенов;
- не решает, дорого ли читать репозиторий: печатает числа и отдаёт решение шагу 4;
- не судит код и не догадывается: чего правило не покрывает, то объявлено `no-rules`/`ambiguous`.

## 5. Что доказывает готовность

1. `node --test` зелёный целиком.
2. Живой прогон **в другом проекте** (не в этом репозитории) доходит до `.agent/survey-plan.json`,
   и в плане есть клетка `spine` с манифестом сборки — единственный тест, ловящий дефекты якорения cwd.
3. Швы проверены внесением дефекта: вернуть плоскую резку → юнит устойчивости id краснеет; убрать
   исключение своего имени типа → два `Model.java` получают ребро друг на друга.
