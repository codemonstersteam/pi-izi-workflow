# Большие репозитории — где полоса встаёт и почему

Замер: `sandbox/eddi` (Quarkus-монолит, 2496 файлов в git, 1595 java). Дата — 2026-08-12, ревизия
полосы — шаги 1-10 (`task → brd → survey-plan → scope → graph → intake → weight → ripple → design →
plan`). Всё ниже — числа живого дерева, а не оценка: воспроизведение в §6.

Вопрос, на который отвечает документ: как полоса работает на проекте такого размера БЕЗ объявленной
модульности — без навыков `vertical-slices` / `program-design` / `architecture`, которые в
`izi-flow` задавали границу изменения сверху.

Ответ: **не работает — встаёт на шаге 6 отказом `blocked`, заплатив за отказ весь бюджет шага 4.**

## 1. Числа

| | eddi | потолок izi-pi |
|---|---|---|
| файлов после `skip.mjs` | 1945 (37.3 МБ) | — |
| ячеек обхода (шаг 3) | **306** | не ограничено (`plan.mjs`, «число ячеек не ограничено») |
| батчей роя (шаг 4) | 39 последовательных | ширина 8 — литерал `workflows/izi.js:482-490` |
| узлов карты (шаг 5) | ~1797 (1576 java + прочий код) | **306** = 115 КБ / 417 Б на узел |
| размер `appgraph.xml` | ~0.7-1 МБ (узлы + 6170 рёбер) | `MAP_CAP_BYTES` = 115 КБ |

Цифра 306 ячеек совпадает с потолком в 306 узлов случайно — это разные шкалы (ячейка ≤ 20 файлов,
узел = 1 файл).

## 2. Где именно встаёт

`ext/index.mjs:960-963` — `mapMeasure(text).overCap` → `{ ok: false, why: "карта … выше потолка
чтения …" }`. `workflows/izi.js:551-553` — `if (!map.ok) exit(err("blocked", …))`.

Индексной формы карты нет и это решение, а не пропуск: `steps/intake/map.mjs`, комментарий «WHY A
MEASUREMENT AND NOT AN INDEX» — цена индексной формы никогда не измерялась, а шов, до которого
дотягивается только синтетическая фикстура, `standards/code.md` писать запрещает.

**Отказ оплачен вперёд.** Шаг 6 — первый, кто читает карту целиком, но шаг 4 отрабатывает до него:
306 вызовов скаута, 39 батчей, ~37 МБ текста в модели (≈10M входных токенов) плюс BRD и наряд на
каждый из 306 вызовов. Полоса тратит весь бюджет обзора и только потом узнаёт, что результат не
влезает в окно следующего шага.

## 3. Почему это про модульность, а не про размер

izi-pi выводит модульность СНИЗУ: модуль = файл (`steps/graph/graph.mjs`), «вертикальный срез» =
связная компонента импорт-графа (`steps/graph/levels.mjs`, «A connected component is the
repository's own VERTICAL SLICE — declared by nobody, computed from what calls what»).

Прогон `newLevels` по java-графу eddi (правило рёбер — суффиксное сопоставление импорта,
`steps/scope/edges.mjs::suffixMatches`):

```
nodes: 1595   edges: 6170
components: 6   | наибольшая: 1243 модуля (78%), 731 «голова»
isolated: 292
в цикле (level 0): 12
максимальный уровень: 8
топ fanout: src/main/java/ai/labs/eddi/backup/impl/RestImportService.java — 51
```

Слои считаются корректно (max level 8, циклов всего 12 — Kahn отработал). Вырождается именно
СРЕЗ: одна компонента на три четверти репозитория с 731 входом не ограничивает ничего. Шаг 8
режет окрестность вокруг seed'ов с тем же потолком 115 КБ (`steps/ripple/ripple.mjs:119`,
`cap = MAP_CAP_BYTES`) — на таком графе он вернёт `over-cap` либо охватит пол-репозитория.

Это и есть дыра, которую в `izi-flow` закрывали навыки:

| навык izi-flow | что давал | чего нет в izi-pi |
|---|---|---|
| `vertical-slices` | срез ОБЪЯВЛЯЕТСЯ сверху, по одному внешнему входу | срез вычисляется из рёбер |
| `program-design` | дерево модулей внутри среза, контракты | уровень «модуль ⊃ файл» отсутствует |
| `architecture` | «изменение живёт в 1-2 модулях» как правило планирования | ширина изменения — следствие ряби, не ограничение |

Разница одной фразой: там граница — ВХОД планирования, здесь — ВЫХОД обзора. На монолите
вычисленной границы не существует, и вычислять её не из чего.

## 4. Попутный дефект: правило `bundled` не ловит формат Vite

`steps/survey-plan/skip.mjs:70` — `/\.[0-9a-f]{8,32}\.(js|mjs|cjs|css|map)$/`. Ожидается
`app.4f3c2b1a.js` (точка + hex). Vite пишет дефис + base64: `index-CeAE4N_O.js`.

В обзор eddi поехали:

```
src/main/resources/META-INF/resources/assets/index-CeAE4N_O.js      7906 КБ
src/main/resources/META-INF/resources/assets/ts.worker-CZFa66va.js  6878 КБ
src/main/resources/META-INF/resources/assets/css.worker-…js         1029 КБ
src/main/resources/META-INF/resources/assets/index-…css              727 КБ
… ~20 ячеек бандла
```

**Самые дорогие ячейки роя — минифицированный фронтенд**: ~15 МБ из 37.3 МБ. Правило `asset`
работает корректно (бинарных файлов в обзоре 0 — шрифты и картинки отсеяны), ломается только
`bundled`. Шов: `skip.test.mjs`, кейс на дефисный хэш; правило чинится одним альтернативным
вариантом регекспа.

## 5. Направления проработки

1. **Сузить обзор до якорей BRD.** `newPlan` уже принимает `subjects`, но его контракт говорит:
   «`subjects` marks the anchors that hit, it is NOT a condition of inclusion». Сделать якоря
   условием включения — обзор идёт по поддереву, а не по репозиторию. Цена низкая, ломает
   инвариант «карта = весь репозиторий», который сегодня держит шаги 6/8/10.
2. **Построить индексную форму карты.** Обещана в `docs/concept.md` («Как карта читается»), не
   построена намеренно. Нужна цена на живом дереве — то самое измерение, которого не было.
   Сама по себе отодвигает потолок примерно на порядок и упирается снова.
3. **Внести объявленную границу.** Уровень «модуль ⊃ файл» — пакет/срез как узел карты, то есть
   вернуть в izi-pi роль, которую в izi-flow играли `vertical-slices` и `architecture`.
4. **Чинить `bundled`** (§4) — независимо от всего остального, ~15 МБ обзора.

Связка: без (3) индексная форма (2) только отсрочит отказ, а (1) даёт работающий прогон на eddi
уже сегодня, ценой явного сужения того, что карта покрывает.

## 6. Воспроизведение

```js
// объём обзора и ячейки
import { skipFile, skipDir } from "steps/survey-plan/skip.mjs"
import { newPlan } from "steps/survey-plan/plan.mjs"
// обойти дерево eddi (пропуская .git), отфильтровать skipDir/skipFile,
// newPlan({ files, spine: [], subjects: [] }) → cells.length, распределение cells[].bytes

// компоненты и уровни
import { newLevels } from "steps/graph/levels.mjs"
// nodes = git ls-files '*.java'; ребро = `^import\s+(?:static\s+)?([\w.]+);`,
// пакет → путь, ровно одно суффиксное совпадение среди nodes (правило edges.mjs)
// newLevels({ nodes, edges }) → components[0].modules, isolated, cycle, level
```

Оба замера — чистые функции этого репозитория над чужим деревом; диска полосы они не касаются и
`.agent/` не пишут.
