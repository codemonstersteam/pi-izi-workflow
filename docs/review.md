# Шаг 11 `review` — критик судит ТРЕБОВАНИЕ, и его вердикт возвращается в полосу

Место шага в полосе — `docs/workflow.md` §3.11: СРАЗУ ПОСЛЕ зелёного `checkFrd`, до шага 7.
Обоснование переезда и разбор, которым он куплен, — `tasks/j6-critic-frd.md`. Здесь: что критик
судит, чего ему намеренно не поручено, почему он зовётся ровно один раз и как замечание становится
починкой.

## 1. Вход, выход, участники

| | |
|---|---|
| вход | `TASK.md`, `.agent/brd.md`, `.agent/staging/frd.xml` + два чек-листа от `reviewForm` |
| выход | `.agent/review.xml` (через `.agent/staging/review.xml`) — `Pass \| Reject(Blocker[])` |
| роль | `critic` — `steps/review/critic.md` |
| гардрейл | `review({ path })` → `steps/review/review.mjs::newReview` |
| бюджеты | `LOOPS` — красная ФОРМА вердикта. Кругов критики нет: вызов один |
| оператор | внутри шага нет |

Плана в входе НЕТ и быть не может: шаг 11 стоит ВЫШЕ шага 10. Репозитория тоже нет — критик судит
требование, а не код.

## 2. Два списка, и оба считает машина

**Список 1 — долг** (`owedItems({ requirements })`): строка на каждое требование `brd.md` с его
`fit`. Вопрос по строке: какой элемент артефакта её ИСПОЛНЯЕТ.

**Список 2 — чего никто не просил** (`unbackedItems({ frd })`): элементы FRD, которых не называет ни
одна строка `<carried by>` — use case, сценарий, дельта, ограничение. Принадлежность транзитивна:
`by="UC1/2"` заявляет весь `UC1`, его сценарии и узлы, через которые они проходят. Пустой `carried` —
пустой список: судить не по чему, а «всё подозрительно» не рассуждение.

Список 2 куплен ручным прогоном роли по артефактам `eddi` (19.08.2026, qwen 27B, $0.04, минута):
прямой ход закрыл все 18 строк долга и НЕ ЗАМЕТИЛ, что в артефакте живёт целый `UC8` —
синхронизация с удалённым инстансом, эндпоинт `/descriptors`, превью, исполнитель, — которого не
просит ни `TASK.md` (23 строки), ни одно из 18 требований. Четыре наряда работы, которую никто не
заказывал. Находка сделана ОБРАТНЫМ ходом; список делает её воспроизводимой.

Каждая строка ОБОИХ списков закрывается ровно один раз — `<covers item node/>` или блокер с этим id.
Открытая строка — красная ФОРМА: «в целом да» написать негде.

## 3. Что критику НЕ поручено, и почему это не экономия

Гардрейл дёшев (ноль токенов) и РЕШАЕТ — это не обсуждается. Но каждый его отказ ниже по полосе
стоит роли: красный шаг 9 — круг дизайнера, красный сухой прогон нарезки — переписывание раздела,
`rework` на гейте 1 — перемотка всей полосы. Один вызов критика дешевле любого из них, и он смотрит
на ТОТ ЖЕ список, что машина, плюс на то, чего машина не видит:

| предмет | машина | критик |
|---|---|---|
| требование унесено | `F11`: строка `<carried>` есть и её адрес резолвится | ИСПОЛНЯЕТ ли названный элемент требование |
| поле в чужой сущности | `F8`: у модуля обязана быть дельта | поле, которого не просит ни одно требование |
| канал use case | `F10`: путь принадлежит узлам сценария | канал, которого нет ни у кого |
| значение словаря | `F5`: у числа назван источник | `invented-value`: значение ЕСТЬ в источнике, а источник его ЗАПРЕЩАЕТ |
| открытый вопрос | `autoFindings` пишет блокер сама | — роль его не повторяет |

## 4. Словарь блокеров — закрытый, четыре кода, один владелец

| код | улика | что значит |
|---|---|---|
| `requirement-not-carried` | номер требования BRD | требование не несёт ни один элемент, или названный носитель останавливается на шаг раньше обещанного |
| `invented-value` | ЦИТАТА источника, который это запрещает, либо утверждение, что никто этого не просит | в артефакте стоит то, чего не обещали |
| `goal-not-delivered` | id элемента FRD | `<post>` недостижим из собственных шагов |
| `open-question` | id элемента FRD | пишет МАШИНА (`autoFindings`), не роль |

`CODE_CULPRIT` у всех четырёх — `frd.xml`, `CODE_OWNER` — 6: у артефакта одна роль, и починку пишет
она. Адреса `operator` нет ни у одного кода — терминальной остановки на вердикте критика не бывает.

## 5. Гардрейл судит ФОРМУ и РАЗРЕШИМОСТЬ улики, а не существо находки

`newReview({ xml, frd, requirements })`:

- **R1** — вердикт и тело согласны: `Pass` без блокеров, `Reject` хотя бы с одним;
- **R2** — код в словаре; неизвестный замыкает СВОЙ блокер (три блокера на один дефект стоят роли
  трёх починок);
- **R3** — `node` резолвится в элемент FRD (`frdIds`); у `open-question` адрес синтетический;
- **R4** — род улики задан кодом (см. §4); текст блокера непуст — иначе рельсе починки нечего нести;
- **R5** — каждая строка обоих списков закрыта ровно один раз; закрытая дважды и сочинённая строка
  тоже красные;
- **R7** — строку закрывает ЭЛЕМЕНТ FRD, а не что попало.

Суждение роли не судится никем: спорить с ним внутри полосы некому, а на гейте 1 сидит человек.

## 6. Один вызов на артефакт, и это правило

Критик не судит починку собственной критики: иначе на каждое замечание приходит новое и полоса
критикует себя вечно.

```
6 intake (свой цикл починки по checkFrd, 0 токенов)
   └─ первый ЗЕЛЁНЫЙ checkFrd → 11 review, ОДИН вызов роли
        ├── Pass  → 7 weight → 8 ripple → 9 design → 10б нарезаемость → 12 gate1
        └── Reject → блокеры в {FEEDBACK} наряда intake с префиксом `critic:`
                     6 intake переписывает артефакт ОДИН раз
                     дальше судит ТОЛЬКО машина — второго вызова критика нет
```

Флаг «высказался» живёт в полосе (`criticSpoke` в `band()`). Единственное исключение — `rework`
оператора на гейте 1: это НОВЫЙ артефакт по новому решению человека, и он получает свой один вызов.

`LOOPS` внутри шага тратится только на КРАСНУЮ ФОРМУ вердикта (неизвестный код, адрес, который никуда
не резолвится). Находка при этом сохраняется, чинится её адрес — `carried` несёт это в FEEDBACK.

## 8. Чего шаг не делает

- не судит план — по плану доказывает исполнимость сухой прогон нарезки (`docs/workflow.md` §3.10б);
- не судит репозиторий: какие сьюты есть и достижим ли узел тестом — гейт шага 6;
- не предлагает, КАК чинить: называет, что не сходится, и адрес;
- не разговаривает с оператором и не останавливает прогон — его вердикт это данные.
