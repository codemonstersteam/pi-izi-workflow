# Эталон: пакет плана DOS-535, собранный руками

Что здесь: `module-tree.xml`, `data-flow.xml`, `PLAN.md` и `check.mjs` — пакет, который я собрал
вручную 21.08.2026 на требовании eddi (`sandbox/runbox/eddi/.agent/frd.xml`), когда старый шаг 9
трижды не свёл план. Проверка сошлась с первого захода: 10 из 10.

**Зачем он лежит в репозитории.** По нему сверяется работа нового шага 9. Сверяется не ТЕКСТ —
формулировки роли будут другие, и это нормально, — а **свойства**:

| свойство | эталон |
|---|---|
| модулей в дереве | 12 (= дельты ∪ узлы сценариев требования) |
| отношение `needs` | разрешается целиком, кругов нет |
| волн работ | 4 |
| потоков | 13 (7 use case + 6 ветвлений) |
| шагов потока | 48 |
| порождаемых значений | 31, у каждого ровно один порождающий модуль |
| кодов отказа | 3, каждый порождён и каждый доехал до статуса |
| вопросов к оператору | 0 — на все три ответил репозиторий |

Как гонять проверку на своих артефактах: положить их рядом с `frd.xml` прогона и запустить
`node .agent/mvp/check.mjs` из корня прогона.

Проект самого шага, который должен научиться делать это без меня, — `docs/plan-design.md`.
Разбор того, как этот пакет собирался, по шагам — `docs/plan.md`.
