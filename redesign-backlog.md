# Бэклог переработки: конвейер до 9C

Нарезка `redesign.md` §6 на тикеты. Формат — `pinout-openapi/docs/design/slice-01-validate/tickets/ticket-03.md`.
Дерево модулей — `docs/phase/plan/plan-app-graph.xml`, поток — `docs/phase/plan/plan-data-flow.md`.

Ревизия 2 (21.08.2026): план прогнан через четырёх критиков; их находки внесены. Из первой версии
бэклога изменились нумерация, порядок волн и число тестов — три вещи, о которые она сломалась бы.

**Граница поставки.** Всё до `plan/flows` (9C) включительно. `plan/book`, `review`, `gate1`
объявлены в дереве с `ship="0"`, тикетов на них здесь нет, и **голова их не зовёт**: мост на
неизвестный `id` обязан вернуть отказ, иначе прогон кончался бы ошибкой на успехе.

**Формула тестов** (`tasks/redesign.md`, статья «Правильность программы»):

| род | сколько | на что |
|---|---|---|
| компонентный, шаг С ролью | **3** | успех · гардрейл поймал нарушение · обрыв ЛЛМ (круг НЕ тратится) |
| компонентный, шаг с ПАРАЛЛЕЛЬНЫМИ порциями | **4** | те же три, но обрыв раздваивается: одна порция из семи · все |
| компонентный, шаг БЕЗ роли | **2** | успех · гардрейл поймал нарушение |
| юнит гардрейла | **1 happy + Σ ветвей + 1 молчание на внешний операнд** | судья на ПРАВИЛО, не на шаг |
| шов | по правилу | правило дизайна краснеет при нарушении |

**Молчание — обязательная третья ветвь** (`standards/guardrail.md`): при отсутствующем операнде
правило обязано молчать, а не краснеть (тупиковый блокер, который роли нечем закрыть) и не зеленеть
(мусор проехал).

### TICKET 01 — снять записанные ответы ролей, пока действующий конвейер жив

**io:** proc → тестов нет; приёмка — файлы на диске.

Первым не из аккуратности. Действующий конвейер — **единственный источник** записанных ответов, а
T20 его сносит. Снять их после — значит не иметь заглушек ни для одного компонентного теста, кроме
дерева, и волна 9 встанет на первом же шаге.

**Контекст (только сбор фикстур):**
- один живой прогон на eddi по `standards/runbox.md` до `flows.xml` с включённым логированием
  нарядов и ответов; из журнала хоста
  (`~/.pi/workflows/projects/<slug>/sessions/<sid>/runs/<runId>/journal.json`) достаются: наряд,
  ответ роли дословно, число токенов входа/выхода/рассуждений.
- на каждый ролевой шаг (`brd`/gilb, `scope`/scout, `intake`/intake ×4 пласта, `plan/values`/valuer,
  `plan/flows`/flow-designer) в его `component/` кладутся: `fixture/` — артефакты на входе шага,
  `order.txt` — собранный наряд для чтения человеком, `answer-<модель>.txt` — ответ дословно.
- у `plan/tree` это уже есть (`answer-qwen.txt`, qwen3.6-27b, temperature 0, 6 120 / 7 835 токенов,
  из них 6 462 рассуждений) — образец формы и объёма.
- **ответ не правится руками.** Портить его будет ТЕСТ, в открытую, на именованном дефекте.

**Зависимости:** нет.

**Инструкция:** прогон → выемка из журнала → раскладка по `component/` → в шапке каждого файла
записать модель, температуру и цену. Кода не трогать.

**Verify:** `find steps -name 'answer-*.txt' | wc -l` ≥ 7

**Acceptance:**
- **Контракт:** заглушка компонентного теста — записанный ответ, а не выдуманный
  (`standards/component-test.md`). Выдуманный проверяет наши ожидания от модели; записанный — модель.
- **Вход:** живой прогон на eddi. **Выход:** по три файла на ролевой шаг.
- **Гардрейлы:** здесь их нет — это сбор материала.
- **Готово, когда:** у каждого ролевого шага первой поставки лежит ответ его роли, и в шапке файла
  видно, какая модель, при какой температуре и за сколько токенов его дала.

### TICKET 02 — стандарт проектирования шага: двенадцать правил, которые нарушать нельзя

**io:** none → тестов нет (документ; его исполняемая часть — швы тикета T09).

**Контекст (только эти четыре файла):**
- `standards/workflow-design.md` — НОВЫЙ. Двенадцать правил из `redesign.md` §5, у каждого имя шва.
  Правила 9–12 (`пятёрка тотальна` · `рой литерален` · `шаг судит свой вход` · `имя роли известно
  хосту`) куплены разбором критиков и без швов не ловятся ничем, кроме живого прогона.
  Плюс форма пятёрки `inputs → cut → order → ask → judge → route` и **явно легальная вырожденная
  форма**: шаг без роли не имеет `order` и `ask` — это частный случай, а не нарушение, иначе шов
  правила 1 отобьёт `task`, `graph`, `weight`, `ripple`.
  Плюс граница `next`/`fold` одной фразой: **`next` решает и готовит доставку, `fold` принимает
  ответ и судит.** Формулировка «`next` чистая» запрещена — она краснеет на первом же шаге.
- `standards/component-test.md` — ПРАВКА: шаг это ОДИН каталог, компонентный тест внутри него
  (как сегодня у `steps/plan/tree/`), заглушка становится приводом `next`/`fold`, и добавляется

    inputs.mjs cut.mjs order.mjs route.mjs     пятёрка
    judge.mjs  judge/T1.mjs … T5.mjs           судья на ПРАВИЛО
    order-tree.tpl  order-tree.fix.tpl         шаблоны, читаются module-relative

- `standards/workflow.md` — ПРАВКА `$START_STEP_SHAPE`: он описывает снесённую форму шага.

### TICKET 03 — конструкторы значений: `instruction`, `verdict`, `err`, `portion`

**io:** none → юниты по формуле, ~12.

Ставится ПЕРЕД состоянием: состояние держит вердикты и порции, а значит должно строить их
конструкторами, а не литералами.

**Контекст (только этот модуль):**
- **valid by construction объявлен для одного значения из шести** — это дефект, а не упущение.
  Привод делает `it.do` на том, что приехало; инструкция без `text` и без `role` проходит шов
  словаря и падает уже в `agent(undefined, {role: undefined})`.
- контракт:
  - `instruction.of(raw)` — антецедент: слово из закрытого словаря (`role · roles · ask · say ·
    done · err`) И поля ЭТОГО слова (`role` → `role`, `text`, `staging`; `roles` → `calls` длиной
    ≤ ширины роя; `ask` → `name`, `prompt` ≤ 1024 байт, `items`).
  - `verdict.of(raw)` — антецедент: `ok` есть всегда; при `ok:false` блокеры НЕПУСТЫ; названы `step`,
    `scope` (`portion|whole`), `id` порции, `round`. Гардрейл, молча отбивающий без блокеров,
    оставляет наряд починки пустым.
  - `err.of(kind, fields)` — антецедент: `kind` из закрытого списка `blocked · invalid · question ·
    lookup · escalate · crashed`. Сегодня этот список живёт только в `ENVELOPE` для ролей, а коды
    головы не сведены нигде.
  - `portion.of(raw)` — антецедент: `id` (СТРОКА: `UC1`, не номер) и staging-путь.
- **юнитов: ~12** = happy на каждый конструктор + ветвь на каждый антецедент.

**Зависимости:** T02.

**Инструкция:** написать юниты → реализовать четыре конструктора → зелено → стоп.

**Verify:** `node --test ext/values.test.mjs`

**Acceptance:**
- **Контракт:** невалидное значение НЕ создаётся, возвращается `err`; исключений нет.
- **Вход:** сырые поля. **Выход:** `Result<Value, Err>`, сериализуемый в JSON.
- **Гардрейлы:** конструктор сам себе гардрейл.
- **Готово, когда:** ~12 юнитов зелены; `verdict.of({ok:false})` без блокеров отбит; `instruction.of`
  на слове вне словаря отбит С ИМЕНЕМ слова.

### TICKET 04 — `state`: владелец формы состояния и истории

**io:** fs → ~9 юнитов.

**Контекст (только этот модуль):**
- контракт: `start({cwd,args})` · `put(state,patch)` · `close(state,step,artifacts)` · `resume(cwd)` ·
  `verdicts(state)`. Форма — `plan-data-flow.md`, «Ход конвейера».
- **`at` держит путь И sha1.** `close` считает отпечаток при продвижении; шаг-потребитель сверяет его
  первым ходом. Без этого «вход зелен» — комментарий, а правленый руками артефакт проезжает всю
  оставшуюся полосу.
- **`portions` — СПИСОК** `{id, staging, status, round, blockers}`, а не два счётчика: у 9C порция
  адресуется строкой и семь конвертов приезжают разом. Список закрывает заодно адресата блокера,
  пропуск зелёной порции и вопрос от одной порции при живых соседях.
- **`round` — у порции**, иначе первая съедает бюджет шага и порции 3–4 не пробуются ни разу.
- **`question` — поле состояния** `{of, name, items, retry}`; без него рельса `ask` недостижима.
- **`budgets` — полный словарь** (`loops`, `intakeLoops`, `questionRounds`, `checkpointRetries`,
  `maxParallel`, `reviewRounds`, `orderCap`), а не три поля: `intakeLoops` куплен прогоном e132f0a1,
  `checkpointRetries` держит переспрос, `maxParallel` — ширину роя.
- **границы-часовые пропускаются на единицу дальше предела** (`round ≤ loops+1`): иначе состояний
  `escalate` и `done` не существует, и обе терминальные ветви `next` недостижимы.
- `start` уносит прошлое в `.agent/prev/` и **чистит `.agent/staging/`**: незаконченный черновик не
  наследуется никогда, иначе он судится как ответ этого круга.
- **юнитов: ~9** = happy + чужой `cwd` + круг сверх бюджета + порция сверх состава + неизвестное имя
  шага + четыре ветви возобновления (снимка нет → чистый старт; снимок от чужого `cwd` → отказ;
  снимок расходится с трейсом → отказ с именем шага; шаг в `closed`, но sha1 не совпал → шаг
  переигрывается).

**Зависимости:** T03 (вердикты и порции строятся конструкторами).

**Инструкция:** написать юниты → реализовать → зелено → стоп.

**Verify:** `node --test ext/state.test.mjs`

**Acceptance:**
- **Контракт:** пять функций; `put` не мутирует вход (юнит happy сверяет исходный объект после вызова).
- **Вход:** `{cwd,args}` либо `State` + патч. **Выход:** `Result<State,Err>`, сериализуем в JSON.
- **Гардрейлы:** конструктор; отказ значением, не исключением.
- **Готово, когда:** ~9 юнитов зелены; `resume` по трейсу восстанавливает то же состояние;
  переигрывание шага при разошедшемся sha1 доказано юнитом.

### TICKET 05 — `runlog`: XML-трейс прогона и ЕДИНСТВЕННЫЙ источник истины

**Контекст (только этот модуль):**

  `verdict(код, блокеры)` · `end(статус)` · `read(cwd)`.
- **каталог на прогон:** `.agent/runs/<runId>/runlog.xml`. Один файл на проект означал бы либо второй
  корень `<run>` и невалидный XML, либо затёртый трейс первого прогона — а он источник заглушек для
  всех компонентных тестов.
- **отказ записи не проглатывается молча:** следующая удавшаяся запись несёт `<gap lost="N"/>`.

- **трейс — источник истины при возобновлении**, снимок состояния — кэш. Двух ответов на «с чего
  продолжать» быть не должно: три сегодняшних механизма и есть та болезнь, которую лечим.
- **юнитов: ~5** = happy round-trip + запись без имени шага + длинный текст режется с отметкой +
  отказ записи даёт `<gap>` + `read` на оборванном на середине файле.

**Зависимости:** T03.

**Инструкция:** написать юниты → реализовать → зелено → стоп.

**Verify:** `node --test ext/runlog.test.mjs`

**Acceptance:**

- **Вход:** событие хода. **Выход:** запись; `read` возвращает структуру, а не текст.

- **Готово, когда:** ~5 юнитов зелены; тестом из трейса достаётся `llm`-ответ и он равен записанному —

### TICKET 06 — `bridge`: 55 экспортов → три функции, и таблица, куда делись остальные

**io:** fs → 3 юнита.

**Контекст (только эта граница):**
- контракт: `stepStart({args})` · `stepNext({id,state})` · `stepFold({id,state,event})`. Больше
  расширение не ЭКСПОРТИРУЕТ ничего.
- **но регистрирует — да:** тул `izi_answer` остаётся (без него оператор физически не может
  ответить), и `roleDirectories` остаётся, но состав считается ИЗ ДЕРЕВА `steps/**` (файл `*.md`

  несуществующим — расширение перестало бы регистрироваться, а `catch` на краю сказал бы
  «перезапусти pi», что неверно.
