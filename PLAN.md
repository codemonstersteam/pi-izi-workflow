# План доработки: проектирование по контрактам

Аудит нашёл 10 дефектов проектирования. Все — нарушения стандарта `ts-skill.md`.
Ни один не чинится тестом; каждый чинится изменением контракта.

## Критические (данные теряются / ложная зелёность)

### 1. applyAnswers — молчаливый no-op
Постусловие «ответы вписаны» не проверяется. Функция возвращает исходный план
при несовпадении regex — ответы теряются молча.
→ Result<{plan, applied, total}>, вызывающий проверяет applied === total.

### 2. ctx.agent без outputSchema в plan.ts и execute.ts
ENVELOPE объявлена как мёртвый код — не передана в opts. Ответ роли — Raw.
→ Передать outputSchema: ENVELOPE. Импорт из одного места.

### 3. continue инкрементирует round — обрыв тратит круг
Инвариант «обрыв не тратит круг» заявлен, но for-loop инкрементирует.
→ while + явный round++ только при красном судье.

### 4. repairOrder может получить пустые blockers
Предусловие «blockers непусты» не сформулировано.
→ При пустых blockers использовать planOrder, не repairOrder.

## Важные (ложная зелёность)

### 5. git() ошибки → судьи (b)/(c) молча проходят
git() глотает исключения → пустой diff → «зелёный».
→ gitHead → Result; judgeSolve при since="" → блокер.

### 6. includes("Ф1") — Ф10 закрывает Ф1
Префиксное совпадение.
→ RegExp \bФ\d+\b — точное покрытие.

### 7. readAt "" двусмысленность
Файл отсутствует = файл пуст.
→ Result<string | null>.

### 8. askWithRetry .some() — частичные ответы
Одна непустая строка из пяти принимается как успех.
→ .every() — все или ничего.
