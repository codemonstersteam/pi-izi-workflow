## Что сделать

### Правило 12 — `steps/design/values.mjs::checkValues`: каждый конец use case закрыт

Грамматика словаря получает атрибуцию — приём `covers`/`witness` шага 11:

```xml
<value id="v15" text="Карточка(name,description)" closes="UC2/post"/>
<value id="v16" text="Карточка не отображена" closes="UC2/3a"/>
```

Токены — `UCx/in` (первый `<step>`), `UCx/post` (последний), `UCx/<extId>`; несколько через пробел.
Машина считает покрытие множества, которое `parseFrd` уже отдаёт (`usecases[].id`,
`usecases[].exts[].id`): каждый конец закрыт хотя бы одним значением — иначе блокер, цитирующий текст
`<post>`/`outcome` (роли есть из чего сформулировать строку); токен, не резолвящийся в FRD, — блокер
(зеркало правила 1). `parseValues` кладёт `closes` НА Map, как уже ездит `dups`.

Расширение ФОРМЫ — обход потребителей по констрейнту 5, все названы: `parseValues` (расширяется),
`ext/index.mjs::design` (все три ветки читают через него — менять нечего), `nodes.mjs::cards`
(id→text, не трогает), сборка `design.mjs` (текст по id — сдаточная форма §4/§5 не двигается ни на
байт), наряды B и C получают `VALUES` текстом, атрибут им виден и проходу B полезен.
`core/xml.mjs::attrs` незнакомых атрибутов не роняет.

### Правило 13 — `steps/design/nodes.mjs::checkGraph`: закрывающее значение поселено

Значение с `closes="UCx/post"` или `closes="UCx/<extId>"` обязано стоять в `out` хотя бы одного узла
из `nodes` сценариев этого use case; значение с `closes="UCx/in"` — в `in` такого узла. Операнды —
`scenario.uc` и `scenario.nodes` из `parseFrd`, те же, что у R7 шага 11.

Это машинная форма основания 3 §4 (`docs/data-flow.md:94-102`) для концов. На этом прогоне `v15`/`v16`
принудительно попадают в `out` страницы (S2 несёт её в `nodes`), и ловушка Д2 распадается: маршрут
`v2 → html@v1 → Res@v13 → html@v15` доставляет `v13` (правило 10), а возврат не даёт прямого участка
(правило 9). Красный чек B — вина B по конструкции, `blameOf` не трогается.

### Правило 14 — `steps/design/nodes.mjs::checkGraph`: узел, обязанный лежать на маршруте, имеет чем ходить

Структурный инвариант, дешевле правила 13 и не зависящий от атрибуции: **узел с `delta` несёт хотя бы
одно значение в `out`; путь из `frd.touched` присутствует в графе и тоже несёт непустой `out`.**

Основание — грамматика следующего прохода, а не вкус: шаг пишется значением из `out`
(`routes.mjs:231`), и одновременно правила 2 и 5 требуют этот узел на маршруте. Пустой `out` у такого
узла — состояние, из которого у прохода C нет ни одного легального файла. Судит это тот, кто может
починить: гардрейл B, до всякого router'а.

Правило 14 шире правила 13 и не заменяется им: правило 13 срабатывает только когда узел упомянут в
`scenario.nodes` какого-то use case с `<post>`; delta-узел вне всех сценариев и `touched` путь,
которого в графе нет вовсе, проваливаются в ту же ловушку мимо правил 12 и 13.

### Переадресация ПОВТОРНОГО правила 10 — `workflows/izi.js`, `$START_BLAME`
