# Шаг 2: что об этой задаче известно науке и индустрии

Две разведки, 22.08.2026. Первая — литература и продовые системы. Вторая — замеры по нашему
репозиторию `sandbox/runbox/eddi` (1854 файла, эталон — 10 файлов, где реально лежит работа
DOS-535). Здесь только выводы; решения по ним — в `steps/brd/data-flow.md`.

## Глава 1. Как эта задача называется

**Главное имя — feature location (concept location):** по описанию свойства словами найти места в
коде, где оно должно жить. Каноника — Dit, Revelle, Gethers, Poshyvanyk, «Feature Location in Source
Code: A Taxonomy and Survey», JSEP 2013.

Наш шаг 2 совпадает с её подзадачей буквально: **search term identification for concept location** —
из текста заявки выбрать 3-7 слов, которыми пойдёт поиск. Работа STRICT (Rahman & Roy,
arXiv 1807.04475) делает ровно это через TextRank поверх текста заявки; их Top-10 accuracy —
30-57%. Теоретическое имя самого разрыва «человеческое понятие ↔ его реализация» — **concept
assignment problem** (Biggerstaff, Mitbander, Webster, ICSE 1993).

Что нам НЕ подходит и почему:

| дисциплина | почему не она |
|---|---|
| traceability link recovery | предполагает, что артефакты уже спарены; у нас пары нет, её и строим |
| change impact analysis | стартует от уже известного элемента кода; у нас его нет — это наши R1..Rn, а не якоря |
| software reconnaissance | добывает якоря из трасс выполнения «фича вкл/выкл»; у нас нет запуска |
| IR-based bug localization | та же математика, но вход — баг-репорт по существующему коду |

## Глава 2. Алгоритмы, которые сюда ложатся

**IDF — числовая замена вкусу.** `log(N/df)`: `version` при 668 файлах из 1854 даёт 1.0, `glossary`
— 7.53, `config` — 0.51. Отбраковка широкого якоря перестаёт быть суждением роли. Обоснование —
Robertson, «Understanding IDF», J. Doc. 60(5) 2004. Слепота IDF: редкая опечатка получит
максимальный вес.

**BM25 вместо TF-IDF**, если ранжируем файлы: насыщение частоты и нормировка на длину — 20
упоминаний в одном файле не делают его в 20 раз релевантнее. **BM25F / BLUiR**: совпадение с именем
класса весит больше, чем совпадение в комментарии — самый дешёвый прирост точности из известных.

**Query expansion через pseudo-relevance feedback:** взять топ помеченных файлов, вытащить из них
частые идентификаторы, дописать вторым проходом. Находит то, чего заказ не называл. Плата — дрейф
запроса, если первый проход мусорный.

**Spreading activation по зависимостям** (Suade, Robillard, TOSEM 2008): растекаться от помеченных
файлов по структурным связям, подавляя популярных соседей. Это готовая формула роста клетки:
специфичный сосед внутрь, хаб наружу.

**Расщепление идентификаторов:** `GlossaryConfigService` → glossary + config + service. Иначе якорь
промахивается мимо половины совпадений. Цена — десяток строк.

**Что не берём сейчас:** learning-to-rank (нужен размеченный корпус из сотен решённых задач),
инвертированный и триграммный индексы (грeп по 1854 файлам стоит 0,56 с — индекс окупится на
порядок большем репозитории).

## Глава 3. Чем меряют — и что дёшево нам

**Селективность разметки** — доля помеченного репозитория, считается на каждом прогоне бесплатно,
эталон не нужен. Ловит обе болезни разом: «помечено полрепозитория» и «не помечено ничего».
Коридор — порядка 0,5-5%.

**Precision / Recall @ K, MRR, Top-K accuracy** — требуют эталонного списка файлов. Держим для
задач, где эталон есть, как меру переделок; на каждом прогоне не считаются.

## Глава 4. Замеры по нашему репозиторию

**Аналог надо грепать по тексту — это сразу карта обхода:**

| приём | отобрано файлов | эталон найден | precision |
|---|---|---|---|
| совпадение по пути, как в `focus.mjs:45` | 263 | 1 / 10 | 0,4% |
| файлы аналога по пути, `focus.mjs:350` | 10 | 0 / 10 | 0% |
| **грeп `PromptSnippet` по тексту** | **62** | **10 / 10** | 16% |
| IDF-top50 по шести якорям | 50 | 8 / 10 | 16% |
| со-встречаемость ≥4 якорей в файле | 45 | 8 / 10 | 18% |

Стоимость — 0,56 с и ноль токенов.

**Кандидаты в якоря берутся из нормализованной таблицы, а не из сырого заказа.** По русскому
`TASK.md` слово `export` не попадает в кандидаты вообще; по таблице — попадает и даёт 92 файла.
`import` при этом честно вылетает как java-keyword в 85% файлов.

**Составное имя надо резать префиксами:** таблица пишет `PromptSnippetService` (29 файлов), а
ценный якорь — `PromptSnippet` (62).

**Словарь репозитория** (`vocabularyOf`, 51 мс) знает то, чего нет ни в заказе, ни в таблице: 7 из
10 файлов эталона лежат в пакете `backup`, и ни один якорь из заказа туда не смотрит.

**Клетки:** 62 помеченных файла лежат в 24 клетках; взять их целиком — 256 файлов и 3,26 МБ против
1,5 МБ самих файлов, разбавление ×2,2. Тринадцать клеток из двадцати четырёх несут ровно одно
попадание.

## Глава 5. Что делают в проде

| система | что взять |
|---|---|
| zoekt / Sourcegraph, GitHub Blackbird | правило селективности якоря как жёсткий валидатор, а не совет |
| BugLocator (SimiScore) | «похожий уже решённый случай» — это наш `analogue`, и он даёт второй запрос |
| BLUiR | код разложен на поля: класс, метод, переменная, комментарий — веса разные |
| Facebook Aroma | дешёвый широкий отбор → дорогое уточнение только на кандидатах |
| Suade | правило роста клетки: специфичный сосед внутрь, хаб наружу |
| LocAgent (ACL 2025), Claude Code | векторный поиск выброшен: греп + агент по графу. Качество решает запрос, а не движок |
