# Шаг 2 (brd): во что его переделываем

Черновик. Решение принято по замерам, не по вкусу. 22.08.2026.

## Суть

Шаг перестаёт быть писателем BRD и становится **семантическими воротами**: он отвечает на один
вопрос — «эту задачу вообще можно решить в ЭТОМ репозитории?» — и выдаёт наверх якоря, по которым
дальше работают шаги 3/3b/4.

Четыре изменения, каждое подтверждено замером на задаче eddi:

| # | что меняем | почему |
|---|---|---|
| 1 | Вердикт из трёх: `solvable` / `unclear` / `not-this-repo` вместо полного BRD | несущий выход шага — `subjects[]`, а не измеримые требования; требования достаются на intake |
| 2 | В наряд кладём **таблицу попаданий**: словарь репозитория со счётчиками | роль берёт якоря из фактов о репозитории, а не из головы. Без таблицы — 0/6 якорей, с таблицей — 5/6 |
| 3 | На провод уходит **английский**: русский вход → перевод qwen → отправка. И задача, и ответы оператора | русская задача против английского репозитория даёт якоря, которые ни во что не попадают |
| 4 | `reasoning: {effort: low}` + чек-лист самопроверки в роли | старая роль жгла 8304 токена рассуждений из 8797 |

### Чем это измерено (задача eddi)

| прогон | якорей от эталона | сек | выход | рассуждения |
|---|---|---|---|---|
| старая роль, русская задача | 4/6 | 121 | 8797 | 8304 |
| ворота, русская, без таблицы | 0/6 | 21 | 1522 | 1365 |
| ворота, русская, с правилами | 2/6 | 26 | 1933 | 1656 |
| **ворота, английская + таблица** | **5/6** | **21** | **1438** | **836** |

Эталонные 6/6 в `component-tests/etalon-eddi/.agent/brd.md` — правленые руками: старая роль на
старой задаче даёт 4/6. Это проверено прогоном, а не выведено.

## Что ещё не сделано

- **Гардрейл на ворота не написан.** Все три находки прошлого прогона поймал глаз, а не проверка.
  Нужен `judge`: вердикт из трёх · следствие, а не пересказ задачи · новая сущность обязана быть в
  якорях · `analogue` обязан иметь ненулевой счёт в таблице попаданий.
- **Переводчик не модуль конвейера.** Файлы `/tmp/sq/t*.md` переведены вручную. Нужен шаг-приставка:
  вход русский → qwen переводит → дальше идёт английский.
- Компонентный тест шага (`steps/brd/component/`) написан под старую форму — переписать под ворота.

## Три вида задачи

| # | вид | репозиторий | задача | эталон BRD |
|---|-----|-------------|--------|------------|
| 1 | большой живой репозиторий, задача на русском | `../sandbox/runbox/eddi` | `../sandbox/runbox/eddi/TASK.md` | `component-tests/etalon-eddi/.agent/brd.md` |
| 2 | новая точка входа в маленьком репозитории | `../sandbox/runbox/quarkus-rest-json-app-v2-t2` | его `TASK.md` | его `.agent/brd.md` |
| 3 | новая страница + связь со старой | `../sandbox/runbox/quarkus-rest-json-app-v2-t3` | его `TASK.md` | его `.agent/brd.md` |

Они специально разной природы: (1) шум и масштаб, (2) один эндпоинт, (3) UI плюс переход.
Ворота обязаны дать `solvable` на всех трёх и якоря, попадающие в эталон.

## Как прогнать эксперимент

Стенд лежит в `/tmp/sq/`. Прогон — это три команды на одну задачу.

```bash
export OPENROUTER_API_KEY=...            # без него ask.py падает сразу

# 1. Наряды: старый (русский, без таблицы) и ворота (английский + таблица попаданий)
node /tmp/sq/prep.mjs <repoDir> <englishTaskFile> <tag>
#    печатает: файлов N | кандидатов N | в таблице N | размеры обоих нарядов

# 2. Ответ модели. Роль -> наряд -> файл ответа -> метка для таблицы времени
python3 /tmp/sq/ask.py steps/brd/gilb.md /tmp/sq/order-gate-<tag>.txt /tmp/sq/out-gate-<tag>.md ворота-<tag>

# 3. Сравнение с эталоном: секунды, токены, требования, попадания якорей
node /tmp/sq/score.mjs
```

Конкретно по трём задачам:

```bash
node /tmp/sq/prep.mjs ../sandbox/runbox/eddi                        /tmp/sq/eddi-en.md t1   # файла пока нет — задачу eddi надо перевести
node /tmp/sq/prep.mjs ../sandbox/runbox/quarkus-rest-json-app-v2-t2 /tmp/sq/t2.md   t2
node /tmp/sq/prep.mjs ../sandbox/runbox/quarkus-rest-json-app-v2-t3 /tmp/sq/t3.md   t3
```

Правила стенда, оплаченные ошибками:

- **Один прогон за раз, в переднем плане.** Фоновый `nohup` в этой оболочке умирает вместе с ней —
  шесть прогонов подряд дали пустой лог и ноль ответов.
- **Своё имя файла запроса на каждый прогон.** Два скрипта на одном `/tmp/req-brd.json` затирают друг
  друга, и сравнение остаётся убедительным на вид и недействительным по сути.
- Один ответ модели — 20–120 с. `--max-time 600`, три попытки на случай, если `write` не вызван.
- Осиротевший `curl` переживает `pkill` родителя. Проверять `ps` перед новым прогоном.
