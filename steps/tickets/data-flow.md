# Шаг 14 — как работает алгоритм, фаза за фазой

Операционный контракт шага: что приходит на вход каждой фазы, что она обязана отдать и кто её
исполняет. Формулировки здесь НЕ ЗАВИСЯТ ОТ ПРОЕКТА: по ним пишется код, который работает на любом
репозитории — команда проверки, имена модулей, язык и стиль приходят из артефактов, а не из этого
файла. Место шага в полосе — `docs/workflow.md` §3.14; замеры на живых формах — `docs/design.md`.

**Задача шага: нарезать план на тикеты для СЛАБОЙ модели** — так, чтобы шаг 15 раздавал их
механически, не читая тело, и запускал параллельно всё, что параллелится.

**Роли на шаге нет. Ноль токенов.** Все решения приняты раньше: что менять — шаг 6, как менять —
фаза ④ шага 9, в каком порядке — фаза ⑦, можно ли вообще — гейт 1. Здесь только раскладка.

**Тикетов два рода, и разделение живёт НА ГРАНИЦЕ.** Отдельный тестовый тикет перед модульным ломает
компиляцию: тест ссылается на класс, которого ещё нет, и его «красный» — ошибка сборки, а не
проверка. Эмуляция 35 нарядов живого прогона нашла это на четырёх тикетах, чьи ворота недостижимы на
их волне.

```
boundary   чёрный ящик через канал актёра, волна 0, пишет НЕ тот, кто пишет код
module     код и его тесты в одном тикете, волна = слой графа «зовёт»
```

Неподгоняемость сохранена там, где она работает: граничный тест не знает ни одного нового класса,
поэтому его нельзя подогнать под реализацию — её ещё нет.

Приём сверен с двумя зрелыми конвейерами (`rationaldev-ai-sdlc-skills`, `oh-my-openagent`): оба
независимо держат юнит-тест в тикете модуля, а неподгоняемую проверку выносят на границу программы.
Не взято то, что относится к гринфилду — `scaffold`, `wiring`, `README`: полоса правит СУЩЕСТВУЮЩИЙ
репозиторий.

## ① Разбор плана — скрипт

| | |
|---|---|
| **вход** | `task/<КЛЮЧ>/design/<партия>.md` — разделы, промоученные фазой ⑤ |
| **выход** | `Section[] = { path, body, calls, closes }` |
| **исполнитель** | скрипт, 0 токенов — `steps/design/card.mjs::sectionsOf` |

Тот же разбор, которым судит гардрейл партии и собирает `PLAN.md` фаза ⑧.

**Отказ:** ни одного раздела — резать нечего.

## ② Слои — скрипт

| | |
|---|---|
| **вход** | `Section.calls` — объявленные рёбра «зовёт» |
| **выход** | `layersOf` → `string[][]`, снизу вверх |

```
слой 0 = модули, не зовущие никого из изменения
слой k = зовут только слои < k
```

Очередь работ фазы ⑦ даёт ЛИНИЮ, слои дают ВОЛНЫ: внутри слоя ни один модуль не зовёт другого,
значит его можно поднимать разом.

---

## ③ Владелец шага — скрипт

Шаг требования принадлежит модулю, через который он **наблюдаем**: закрыватель, которого зовёт другой
закрыватель того же шага, выбывает; среди оставшихся — последний в очереди работ. **Ни слова о виде
модуля** — правило графовое.

Модуль без шагов — норма: его корректность видна через зовущего.

---

## ④ Граница — скрипт

| | |
|---|---|
| **вход** | use case FRD + `<actor via>` + сьют НЕ-`unit` из карты |
| **выход** | `<NN>-boundary-<uc>.md`, волна 0 |

Заводится, когда в карте есть сьют, которым репозиторий гоняет программу снаружи, а у актёра use case
`via` называет **путь** — то есть актёр входит через границу, а не через класс. Оба факта из
артефактов; догадок о протоколе нет.

Шаг достаётся границе по правилу без исключений:

```
внешний вход (шаг 1) и ветка <ext>, у кода которой есть <failure status>   → ГРАНИЦА
всё остальное                                                              → владелец шага
```

Тело не называет **ни одного пути и ни одного класса из этой доработки** — только канал из `via` и
то, что актёр обязан увидеть. Поэтому тест компилируется СЕЙЧАС и краснеет по деловой причине:
канала ещё нет. Ошибка сборки красным не считается.

**Это единственный тест, который пишет не тот, кто пишет код.** Он зеленеет сам, когда лягут все
модули; править его не имеет права ни один другой наряд.

## ⑤ Модульные тикеты — скрипт

| | |
|---|---|
| **вход** | раздел + его шаги + слой + сигнатуры зовомых |
| **выход** | `<NN>-<модуль>.md`, волна = слой + 1 |

**Код и его тесты — один тикет, один исполнитель.** Отдельный тестовый тикет ПЕРЕД модульным ломает
компиляцию: тест ссылается на класс, которого нет, и «красный» получается от сборки, а не от проверки.
Так же устроены оба зрелых конвейера, изученных перед этой правкой.

```yaml
kind: module
wave: <слой + 1>
blocked_by: [<модули, которых он зовёт>]
outputs: [<модуль>, <его тестовый файл>]
verify: <сборка без тестов> && <сьют> -Dtest=<свой тест-класс>
```

Тело — четыре вырезки: **что делаем** (раздел дословно), **чем пользуемся** (сигнатуры тех, кого
зовёт), **что проверяем** (шаги владельца, текст из FRD дословно), **порядок** (сначала тест по
тексту шага, потом код).

**Ворота — сборка и ТОЛЬКО свои тесты.** Никогда чужие: наблюдатель реализуется волнами позже, и
требовать его зелени значит требовать невозможного.

**Модуль без своих шагов закрывается одной сборкой.** Его сигнатуру проверит компилятор потребителя
уже на следующей волне, а форму данных наружу — граничный тест в конце.

---

## ⑥ Гардрейл — скрипт

| # | правило | что ловит |
|---|---|---|
| 1 | модульный тикет на каждый раздел плана, ни одного лишнего | работу без исполнителя |
| 2 | каждый шаг покрыт ровно один раз — границей ИЛИ владельцем | требование, проверенное дважды или ни разу |
| 3 | `outputs` непуст, ни один путь в двух тикетах | двух исполнителей на одном файле |
| 4 | ворота модуля не называют чужой тест-класс | наряд, недостижимый на своей волне |
| 5 | граница не ссылается на то, что создаёт эта же нарезка | тест, который не скомпилируется до кода |
| 6 | `blocked_by` резолвится, волна зовомого строго меньше волны зовущего | наряд, который не станет готовым |
| 7 | каждый путь в `inputs` знает карта или план | приказ прочитать несуществующее |
| 8 | модуль без шагов связан с изменением — его зовут либо он зовёт | работу, которую не проверит ничто |

Связь в правиле 8 считается в обе стороны намеренно: реализацию интерфейса никто не зовёт по имени —
её выбирает контейнер, а зовут интерфейс.

## ⑦ Что получает шаг 15

```
task/<КЛЮЧ>/tickets/
  01-boundary-uc1.md   wave 0 ─┐ граница: RED по деловой причине, компилируется сразу
  …                    wave 0 ─┘
  10-iglossarystore.md wave 1 ─┐ слой 0: ворота — сборка
  …                    wave 1 ─┘
  16-glossarystore.md  wave 2    слой 1: сборка + свои тесты
  24-restimportservice.md wave 4 слой 3
```

Оркестратор читает только заголовки: `wave` — что поднимать разом, `blocked_by` — чего ждать,
`outputs` — что должно появиться, `verify` — чем закрыть. **Ни один тикет не ссылается на другой
тикет** — только на файлы.

**Два инварианта, которые делают полосу исполнимой:**

```
после каждой волны   сборка ЗЕЛЁНАЯ      ← ни один наряд не оставляет репозиторий несобираемым
в конце последней    граница ЗЕЛЁНАЯ     ← требование доказано снаружи тестом, который никто не правил
```

**Отказ шага 14 терминальный.** Роли нет — чинить некому: расхождение тикетов с планом означает, что
разошлись артефакты, и это разбирает человек.
