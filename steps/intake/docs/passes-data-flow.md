`steps/intake/intake.md` (роль одна на все четыре прохода; закон 0 велит писать ТОЛЬКО названный

- **как:** чистая функция от разбора артефакта; правила чужих пластов молчат — их элементов ещё нет;
- **что возвращает:** `{ ok, blockers }`; блокер — `код · элемент · ОБРАЗЕЦ строки`

- **предусловие:** артефакт разбирается как XML; иначе `invalid-frd` с прямым текстом;
- **постусловие:** пусто = пласт A закрыт.

**Что уезжает роли на доработку:** `{FEEDBACK}` = блокеры этого прохода, `{PREVIOUS}` = её же файл
целиком. Ничего из пластов B/C/D.

**Луп:** да, бюджет `intakeLoops`. Из круга в круг переживает счётчик и `wasRed` (повторная находка
= эскалация).

**Вопрос оператору:** да, `<question>` пласта A — кто актёр, что считать успехом, нужен ли use case
вовсе. Уходит немедленно; **проход не открывает B, пока вопрос без ответа**.

# Ворота и полный суд

    A → B   checkFrd(A) зелен И вопросы A отвечены
    B → C   checkFrd(B) зелен И вопросы B отвечены
    C → D   checkFrd(C) зелен И вопросы C отвечены
    D → 7   checkFrd(D) зелен, ЗАТЕМ checkFrd({}) — полный суд без пласта

**Полный суд обязателен**: правила, судящие два пласта сразу (`F3c` — дельта и сценарий, `F10` —
канал и узлы, `F8` — поле и модуль), в проходном режиме видят только свой пласт, и пласты могут
разойтись между собой. Он же судит промоутнутый артефакт при resume (`F9`).

# Куда направлять доработку после критика (шаг 11)

Критик судит требование ЦЕЛИКОМ и не знает о проходах. Маршрутизация — по коду находки и по тому,
какому пласту принадлежит НАЗВАННЫЙ элемент:

| код | элемент в `node` | проход | что переписывается |
|---|---|---|---|
| `requirement-not-carried` | любой | **A** | нужен use case или его шаг |
| `invented-value` | `<usecase>` / `<scenario>` | **A** | лишний use case снимается вместе со своими сценариями |
| `invented-value` | `<field>` / `<failure>` / `<nfr>` | **C** | лишнее значение или код |
| `invented-value` | `<delta>` / `<touched>` | **B** | лишняя работа |
| `goal-not-delivered` | `<usecase>` | **A** | шаги, которыми достигается `<post>` |
| `open-question` | синтетический адрес | **A** | вопрос оператору, роль его не «чинит» |

Правило маршрута — ОДНО выражение (`steps/review/review.mjs::passOf(finding, frd)`), не таблица в
прозе: проход выводится из того, в каком пласте лежит элемент `node`.

Полоса входит в названный проход и идёт от него ВПЕРЁД до D, а не чинит один пласт:

    passOf = A → A · B · C · D → полный суд
    passOf = C → C · D          → полный суд

Причина — элемент нижнего пласта ДОЛЖЕН получить верхние. Находка «требование не унесено» рождает в
A новый use case; у него нет ни дельт, ни величин, ни строки покрытия, и починка одного A выпустит
заведомо красный артефакт. Проходы, которым нечего дописывать, закрываются первым же зелёным судом
своего пласта и круга роли не тратят.

Если элемент принадлежит двум пластам, маршрут — РАНЬШИЙ из них: починка нижнего пласта может снять
находку верхнего, обратное неверно.

**Пласт D адресом не бывает, и это следствие F11, а не решение.** «Строки `<carried>` не хватает»
живёт ровно до шага 11: F11 не выпускает пласт D, пока строка есть не у каждого требования BRD.
Значит у находки критика строка ЕСТЬ и она ЛОЖНА — носителя нет, и пишет его пласт A. Переигран D
будет всё равно: полоса идёт от входа вперёд до конца.

**Правила сопротивления галлюцинациям**, по одному на вид ошибки:
- шаг без владельца и без вопроса — блокер (разность списков, паттерн F11 уровнем глубже);
- узел вне карты и не новый — блокер (выдуманный путь невозможен);
- спорность без вопроса — блокер (двусмысленность решает оператор);
- функция аналога не унаследована и не объяснена — блокер (встречная сверка с репозиторием);
- дельта на узле, которого B1 не выбрал, — блокер (выбор не съезжает назад в прозу).
