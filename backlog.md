# Бэклог

## Шаг 7 `weight` — срез W1–W6

Концепт и полная карточка — `docs/weight.md`. Решение среза: **вес складывается из ФОРМ дельт, а не
из прозы**, и недостающий факт («сломал / дополнил / поправил») приезжает пятой формой словаря, а не
новым атрибутом и не разбором `from`/`to`.

Три расхождения, ради которых срез существует (улики — `docs/weight.md` §2):

| # | что не сходится | доказательство |
|---|---|---|
| A | `Changed` не различает ломающее и аддитивное — обе формы дают `major` | живой FRD S21: обратно совместимая правка ОДНОГО файла заказывает шаг 9 |
| B | `patch` недостижим: он даётся за «ни одной дельты», а F7 требует хотя бы одну | `docs/concept.md` строка 327 × `steps/intake/frd.mjs::checkFrd` (F7) |
| C | вход объявлен `.agent/frd.md`, шаг 6 производит `.agent/frd.xml` | `docs/workflow.md` §3.7, §3.8, §3.10 × `docs/intake.md` §1 |

Порядок жёсткий: сначала словарь (W1) — иначе ядро веса пишется под форму, которой роль ещё не
знает; в конце живой прогон (W6), без него срез не сдан.

### W1 — пятая форма дельты `Fixed` `[СДАНО]`

Один факт, объявленный в ОДНОМ месте, — `FRD_FORM.deltaForms` (`steps/intake/frd.mjs`). Наряд шага 6
подставляет словарь роли сам (`frdForm`, `{DELTA_FORMS}`), поэтому второго места у него не заводится.

- `steps/intake/frd.mjs` — `deltaForms: ["Added", "Changed", "Removed", "Fixed", "Unknown"]`;
  `checkFrd` не трогается: `Fixed` несёт `node`, как `Added`/`Changed`/`Removed`
- `steps/intake/intake.md` — §8 наряда и `$START_LAW`: формы определяются через **эффект для
  СУЩЕСТВУЮЩЕГО вызова** (`docs/weight.md` §3), не через грамматику предложения. В `$START_EXAMPLE`
  роли `Fixed` НЕ показан: у примера про черновики нет исправления дефекта, а придуманная строка
  ради демонстрации слова — украшение, которому роль подражает
- `docs/intake.md` §3 (грамматика) и §4 (строка F3) — словарь из пяти слов
- `steps/intake/frd.test.mjs` — шов: дельта `form="Fixed"` с узлом проходит F3; дельта `form="Broken"`
  краснеет с перечислением ПЯТИ форм

### W2 — ядро `steps/weight/weight.mjs` `[СДАНО]`

Чистое, io не знает; таблица форм — данные модуля, а не `if`-лестница.

- `MODE_TABLE` — `{ Added: "minor", Changed: "major", Removed: "major", Fixed: "patch" }`;
  `RANK` — `patch < minor < major`
- `newMode({ deltas }) -> Result<{ mode, why[] }, "unknown-delta" | "no-delta" | "bad-form">`;
  `why[]` — `op (form)` дельт, давших максимум
- **правило едет вместе с кодом, а не отдельной задачей:** `docs/concept.md` — строка таблицы весов
  «ни одного → patch» заменяется на «только `Fixed` → patch», строка 132 (карточка шага 7) — вход
  `frd.xml`; `docs/workflow.md` §3.7 — карточка переписывается по `docs/weight.md`. Между этим
  срезом и W5 концепт иначе противоречил бы `MODE_TABLE` — то самое второе место для одного правила
- `steps/weight/weight.test.mjs` по формуле `1 happy + Σ ветвей`; швы, которые обязаны краснеть:
  `Added`+`Fixed` → `minor` (максимум, а не первая дельта) · одна `Changed` → `major` · одна
  `Removed` → `major` · только `Fixed` → `patch` (расхождение B не вернулось) · `Fixed`+`Changed` в
  обоих порядках → `major` (свёртка коммутативна) · `Unknown` среди зелёных → `unknown-delta` с `op`
  и `why` · ноль дельт → `no-delta` · форма `Broken` → `bad-form`

### W3 — функция расширения `weight` `[СДАНО]`

`ext/index.mjs`: единственный io шага. Читает `.agent/frd.xml`, разбирает его **тем же**
`parseFrd` (второй копии грамматики нет), судит `newMode`.

- зелёный → пишет `.agent/mode` — одно слово, без перевода строки в конце; возвращает
  `{ ok: true, mode, why }`
- красный → **стирает** стоявший `.agent/mode` и возвращает `{ ok: false, why }`. Стирание — часть
  контракта: `newRun` уносит в `.agent/prev` только состояние прогона, артефакты остаются, и вес
  вчерашнего прогона пережил бы сегодняшний отказ (`docs/weight.md` §4)
- регистрация: `functions: { …, weight }`, `headline`/`description` манифеста расширения
- io-шов в `ext/index.test.mjs` (там же, где шов якоря `context.run.cwd`): `Unknown` → `ok:false` И
  стоявшего `.agent/mode` больше нет. Доказан реинтродукцией: убрать `drop()` — тест краснеет один

## Отложено с объявленным триггером

**Атрибут `breaking="yes|no"` на `Changed`.** Понадобится на первом живом FRD, где существующий
элемент контракта изменился и остался совместимым (`int` → `long`, enum с новым значением). Такого
артефакта не случалось ни разу, и он добавляет второй ФАКТ на дельту — в отличие от `Fixed`, который
даёт смысл уже существующему решению (`docs/weight.md` §3). Вводим по факту, не под гипотезу.

**Цикл 6↔7 на `Unknown`** (вопрос оператору из шага 7 → пере-делегация шага 6). Цена: ещё один
бюджет, петля в программе и вход в `askOperator`. Берём, когда живой прогон покажет `Unknown` чаще,
чем раз в полосу (`docs/weight.md` §5).
