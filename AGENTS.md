# solo — как работать здесь

$START_GOAL
Превратить заказ из TASK.md в принятый оператором план и разработку по нему: модель с полным
доступом к коду пишет PLAN.md по артефакт-спеке, конвейер проверяет. Дизайн и data-flow —
`PLAN.md`; требования к коду — `standards/`.
$END_GOAL

$START_CONTEXT
- Это ПАКЕТ расширения pi-extensible-workflows, не пайплайн с файлами в проекте.
- `ext/` — всё: хост-функции станций (`soloStart/soloNext/soloFold/ask`), команда `/solo`
  (`ext/prompts/solo.md`, inline-скрипт полосы), роли (в папках шагов `steps/*/`), судьи.
- В проект оператора не кладётся НИЧЕГО харнессного: только его TASK.md [+ PROMPT.md] и
  рантайм `.agent/`.
- Установка: `pi install ./ext` — один раз на машину; правка под `ext/` живая после
  рестарта сессии pi.

$END_CONTEXT

$START_RUN
1. `node --test` — зелёная целиком, до любого живого запуска.
2. В каталоге проекта (TASK.md в корне): `pi` → `/solo`.
3. Воркфлоу идёт foreground: чат-модель делает ОДИН tool call (~100 токенов) и дальше не
   участвует; вопросы оператора — TUI.
4. Диагностика на диске: `~/.pi/workflows/projects/<slug>/sessions/<sid>/runs/<rid>/`.
5. Живой прогон вести по `standards/live-run.md`.
$END_RUN

$START_CONSTRAINTS
1. Гардрейл решает, не роль: судьи-скрипты для вычислимого, критик для смысла, оператор
   для решений.
2. В репозитории проекта — ноль харнесс-файлов.
3. Существующие тесты проекта не переписываются; легальная правка обязана быть строкой
   плана (спека раздела 2).
4. Каждая строка Ф плана ↔ коммит.
$END_CONSTRAINTS

$START_FORBIDDEN
- Не возвращать копирование харнесса в проекты (преждений bin/install.mjs).
- Не кормить роли срезами вместо кода: planner/dev читают репозиторий сами.
- Не запускать полосу в foreground: он держит сессию и глушит чат-реле ответов.
$END_FORBIDDEN

$START_SUCCESS
- `node --test` зелёный.
- Живой прогон в чужом проекте: PLAN.md принят оператором, Ф↔коммиты 1:1, тесты проекта
  зелёные, харнесс-файлов в проекте ноль.
$END_SUCCESS
