# Срез `task` — оператор кладёт сырое требование

| | |
|---|---|
| род | `human` |
| вход | — (внешний: человек) |
| выход | `task = TASK.md` — объявляется БЕЗ якоря; `./` добавляет печать `next-step`, иначе якорь склеится с корнем дважды |
| квитанция | `.agent/receipts/task.json` |
| приёмка | `{ cmd: "node steps/task/validate-task.mjs", args: ["{{artifact}}"] }` |

## Контракт среза

**Antecedent.** `TASK.md` существует в корне прогона, непуст, ≤ 300 строк.

**Consequent.**
- success: квитанция написана; `.agent/brd.md` дальше строится из этих байтов **как есть**.
- failure: `too-long` — задачу делит человек, конвейер её не режет; `empty` — молчание не есть
  требование; `absent` — шаг ждёт оператора.

## Дерево модулей

```
ingress   bin/accept.mjs — разбор argv (--step, --root)
head      bin/accept.mjs — труба: снять факты → decideOutcome → исполнить
логика    core/move.mjs::decideOutcome — чистая
          core/steps.mjs::stepState — чистая
io        приёмка steps/task/validate-task.mjs (kind=script в терминах io: fs)
```

**Головной модуль не покрывается юнитами.** Он труба уже проверенных частей; его доказывает
компонентный сценарий через реальный вход.

## Решение, стоившее прогона run-4

У человеческого шага **нет конверта**: оператор кладёт файл и ничего не печатает. Значит:

1. Существование входа судит **приёмка**, у которой есть зонд, а не роутер, у которого есть право
   `read`. Право `read` у роутера закрыто — запрет переехал из прозы в машину.
2. `next-step` различает **два** состояния человеческого шага: `awaiting-operator` (выхода нет) и
   `ready` (выход уже лежит, шаг закрываем). Одна причина на оба случая — это и был тупик run-4:
   харнес печатал «ждём оператора» при живом файле, роутер пошёл проверять сам и ошибся путём.
3. Пути печатаются с якорем `./`. Голое имя есть приглашение угадать корень.

**Красный чек здесь уходит оператору (код 10), а не в пере-делегацию.** Оператора некому позвать
ещё раз: его артефакт чинит человек.

## Тесты по формуле

| модуль | ветви антецедента | по формуле | факт |
|---|---|---|---|
| `stepState` | blocked · awaiting-operator | 3 | **3** ✔ |
| `decideOutcome` | артефакта нет · чек красный | 3 | **5** — превышение, см. ниже |
| гардрейл `validate-task` | — io-труба | 0 | 0 ✔ |

**Компонентные сценарии считаются по ТРУБЕ, а не по срезу.** Это поправка к первой редакции: она
приписывала сценарии шагу, а `bin/accept.mjs` и `bin/compose.mjs` обслуживают ВСЕ шаги разом, и их
сценарии не делятся между срезами. Сегодня: `accept` — 8, `compose` — 5. Ветви контракта у них
общие (коды 0/10/20/2, рельсы, промоут, квитанция), и разносить их по срезам значило бы считать
одно и то же несколько раз.

## Что осталось незакрытым

Прогон может **встать** на этом шаге, не покраснев ничем: если оператор не кладёт файл, полоса
стоит вечно. Машинного признака «стоит, а не висит» нет — сторож видит молчание, а не
непродвижение. Заведено в `backlog.md` первым пунктом.
